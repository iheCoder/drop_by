# 主动性执行与恢复调整（2026-11-08）

本轮在 main 上承接 899561c 的上下文改动。没有重做记忆系统，没有修改人物设定，也没有增加发言配额、人格评分、隐私隔离或跨群分享规则。

## 实际改动

普通真人消息直接进入成员行动，删除每条消息前的公共模型解释步骤。成员使用 `apply_instruction` 落实真人明确的工作调整、暂停/继续、人物设定和组织职责。原有 responsibilities、委托父链、交接、关闭和结果回报继续使用；只有共享状态的写入入口改变。工具回执与状态修改在同一事务提交。删除不再使用的两段公共控制提示词。增加的一句公共说明仅解释接受/交接/撤销职责时怎样记录，不规定主持方式或发言顺序。

一次成员失败只挡住原消息的原地重复尝试；新消息仍给这个成员新的行动机会。同伴的行动不等待它恢复，后来成功也不再保留旧失败为整轮结果。

可恢复的网络错误把原工作置回 pending，保留断点，不另开新探索。HTTP 5xx、429、408、网络超时及连接中断按既有分类恢复。工作层重试沿用 ExploreInterval，默认 30 分钟；请求内沿用三次尝试和 1/2 秒等待（供应商 Retry-After 更长时遵从它）。没有新增网络探测器或重试次数终止线。既有历史 failed 不批量复活。

恢复有新消息或修订变化时，先确认已经成功的工具回执，再把旧的未执行调用标为未执行，交给同一成员结合新现场选择。已发送消息不重复；未确认的写入如实标为未确认。没有新情况则继续消费既有断点，不额外生成一轮重复内容。已停止/替代的工作不恢复；同批后续工具也会检查实际停止状态。成果和原始记录继续保留。

个人活动接收本人参与聊天中的新消息；初次读取从这次行动开始时算起，恢复时从实际交付位置算起，不默认加入历史全集。真人追加消息也可进入原有 Responses steering。等待中的聊天在现有模型/工具调用结束、断点保存后接手，同一成员仍串行；不取消在途写操作。不同成员独立执行。

表情按目标消息确定房间；问题卡允许指定目标聊天。个人活动也能使用二者，省略问题卡目标时使用本人私聊。问题卡采用同一工具调用的稳定消息身份，重复恢复不会重复发送；发布同时保存聊天唤醒。目标成员关系和实际暂停状态仍校验。表情维持原有“不额外唤醒模型”的行为。

默认个人活动时钟保持原值；沉默不退避，不随机伪造不同性格的发言时刻。等待恢复的个人探索不再被新兜底探索取代，未来具体预约仍不阻断普通个人活动。

## 边界与没有改的内容

- 用户停止、原有总预算、同次写入幂等、实际成员归属和资料版本检查保留。
- 网络失败的工作层重试默认仍需等 30 分钟，并非实时检测网络恢复。
- 同一成员交接发生在调用结束的边界；没有强行中断尚在执行的网络或写操作。
- 指令工具沿用现有真人来源、人物编辑和职责范围检查，包括人物说明原有的 3000 字符校验、偏好/任命来源必须是对应聊天的最新真人消息；它不是公共模型审批。任意含糊话语的理解仍由成员完成。
- 问题卡沿用至少两个选项，表情沿用现有图案集合。没有新增选项数量上限。
- 没有清理、恢复或重新执行正式库里的历史失败工作；原人物、记忆、作品和预算配置不改。

## 验证

新增自动测试覆盖：普通聊天不经过公共模型、失败后的同伴新消息、原个人工作的网络恢复、未发送旧稿被新条件替代、停止后的同批消息拦截、个人问题卡/表情及重复调用、共享职责落地、本人聊天在保存边界接手。

原有协调交接、临时/长期范围、撤销职责不取消工作、预算恢复后不覆盖较晚人物编辑等测试继续验证；旧的控制模型替身迁到成员工具/写入边界。全量测试与 race 验证使用独立 SQLite 和模型替身，不向正式群写验收台词。

真实模型验收使用从正式库只读取得的裴船、石粒、青雉、爱情导师设定，使用独立数据库。第一轮发现主持只体现在台词而没有落库，补上简短的工具用法说明；第二轮实际保存并关闭了临时职责，结束时零活跃职责是正常行为，测试改查历史记录。没有要求成员选特定立场、固定轮数或固定发言数量。真实语气仍有解释过多和开场观点相似的问题；短场景通过不代表长期自然度已解决。

最终验证：`go test -race ./...` 通过（53.332 秒），`go vet ./...`、构建与 diff 检查通过。第三轮真实验收通过：一份临时职责实际保存、结束后关闭，裴船/石粒/青雉各 3 条消息，爱情导师 0 条；没有按该数量限流。三轮估算费用分别为 $0.112160、$0.213050、$0.088597，合计 $0.413807。记录位于 `/tmp/dropby-initiative-live/run1/report.json`、`run2/report.json`、`run3/report.json`。第二轮临时职责实际保存并正常关闭，最初的测试断言错误要求它一直活跃，已修正并在第三轮复验。
