# drop_by v0.1 实现与验收记录

验收日期：2026-11-06（Asia/Shanghai）。范围为本机单用户应用，Go 后端、SQLite 持久化与浏览器界面。需求依据为 [产品需求说明 v0.1](demand/drop_by%20产品需求说明%20v0.1.md)。

## 已实现的主流程

1. 根据方向和情境问题创建 AI 成员，保存自然语言身份；同一成员可以加入多个群聊，也可以与用户私聊。
2. 每名成员分别结合身份、经历、当前聊天、现有工作判断发言、探索或保持安静。明确 `@` 有优先回应机会，成员之间可以接话和引用原消息。
3. 实际调用模型、搜索和网页读取；工具请求、成功和失败都保存真实记录。文本成果支持持续修改、历史版本和 Markdown 下载。
4. 用户插话使旧生成失效；“先别聊”与“不用研究”分别控制公开讨论和研究。精确停止短语不依赖模型可用性，其他自然语言结合当前工作解释。
5. 后台执行独立于浏览器连接。服务重启保留原始聊天、工作、成果、记忆与当日预算，未完工作可恢复。单次轮数、每日调用数和费用估算限制约束执行。
6. 浏览器提供成员创建、群聊、私聊、消息引用、历史分页、工具记录、成果版本、未读提示和可选通知；桌面与手机宽度均有可用布局。

在本机 Go 1.27.3 下执行：

```sh
GOTOOLCHAIN=go1.27.3 GOCACHE=/tmp/dropby-gocache go test -race -count=1 ./...
GOTOOLCHAIN=go1.27.3 GOCACHE=/tmp/dropby-gocache go vet ./...

git diff --check
GOTOOLCHAIN=go1.27.3 GOCACHE=/tmp/dropby-gocache go build -o bin/dropby ./cmd/dropby
```

上述检查通过。初版常规测试共 21 个顶层用例；本轮接入审查后增加到 24 个，另有 2 个默认跳过、需显式开启的真实模型用例。测试代码见 `internal/dropby/dropby_test.go` 和 `internal/dropby/live_test.go`。

| 检查范围 | 实际覆盖 |
| --- | --- |
| 用户控制 | 插话后的旧回复、成果和记忆写入被拒绝；停止不依赖模型或剩余预算；局部更正只影响相关工作 |
| 多成员行为 | 无人参与时不强制发言；新事件仍可重新参与；明确 `@` 优先；同一成员跨聊天串行行动 |
| 后台执行 | 无浏览器连接仍完成工作；公开讨论暂停时研究仍可完成；正常退出保留已接受的工作 |
| 持久化 | 研究中断恢复；已完成结果不丢失；完整历史分页；上下文裁剪不删除原始历史；数据目录只允许一个调度进程 |
| 工具与成果 | 实际 HTTP 工具失败保留失败记录；成果版本递增；最后一个模型步骤为已保存成果收尾；部分研究可分享已有进展并保留后续工作 |
| 费用与异常 | 并发预算预留不超限、重启不清空；空白或截断模型 JSON 失败；实际 token 用量结算 |
| 内容与访问范围 | 记忆按成员和场景取用；用户和 AI 不能跨群引用原始消息；本机 Host/Origin 检查；保存内容经过事实归属核对，核对失败不保存 |

确定性用例中的模型替身用于复现并发、取消、错误和边界情况，不能证明真实模型的长期行为品质。生产路径只使用实际模型 HTTP 请求。

## 验收中发现并修正的问题

- **工具执行完成却未及时分享**：早期工具往返上限可能在保存成果后耗尽。现在最后一次模型请求专门收尾，实际未完工作保留后续机会，并为部分研究创建独立分享机会。增加了确定性回归检查。
- **虚构身体经历被其他成员当成证据**：真实聊天出现过“坐过钢管椅”的错误表述。现在消息、私聊、记忆和成果保存前，用实际行动记录核对来源与事实归属；工具返回实际保存的修正后正文，避免后续继续引用未保存草稿。实际用户纠正使成果形成第 4 版。
- **取消请求被误报成网络错误**：响应读取期间的取消现在保留取消语义，正常插话和退出不会被误报为服务失败；退出时已接受工作回到可恢复状态。
- **重复确认与长回复**：参与判断明确区分初次回应和后续机会，已有 `@` 不被视为持续邀请；后续发言需有新论点或新结果，并缩短普通聊天回复。这项改善仍需长期观察。

身体经历的独立真实模型检查也已执行并通过：

```sh
DROPBY_LIVE_TEST=1 GOTOOLCHAIN=go1.27.3 GOCACHE=/tmp/dropby-gocache \
  go test ./internal/dropby -run TestLiveGroundingOfEmbodiedClaim -v -count=1
```

测试输入包含“这是我真实的亲身使用体验”，实际模型将其改为“我没坐过钢管椅”和明确的结构推测。单个样例通过不代表所有幻觉都能被消除。

## 尚未成立的验收结论

- 已验证主要功能链路，没有把“群已经像朋友一样自然、有趣、值得长期打开”当作已完成结论。错落的参与、成员关系积累、内容质量和提醒价值需要持续真实使用评估。
- 跨场景敏感内容识别依赖模型，尚未建立经过验证的保密保证。成员共享同一底层模型，多人一致意见也不是独立事实证据。
- 当前成果是可版本化的文本和 Markdown，没有程序沙箱、第三方账户操作、自动公开发布或浏览器关闭后的系统推送。
- 本机服务必须持续运行，休眠或关机期间不执行。没有部署公网、多用户登录、系统开机自启或外部可用性验收。
- 费用为按配置费率计算的应用账本，不能代替服务商账单；核对事实归属会增加模型调用。定时探索是判断机会，无法保证每次都有值得发布的发现。


## OpenAI 接入复查与交流节奏（2026-11-06）

用户指出模型选择偏向节省成本，要求先快速回应、后续深入思考与探索，并确认每日 3 美元预算。本轮调整默认模型为账号模型列表可见且实际调用成功的 `gpt-5.6-sol`；快速阶段 `reasoning=none`，后续讨论、研究和成果生成 `reasoning=high`。输出与推理总额度分别为 8000 / 25000 token，日调用数上限 600；费用预留仍以每日 3 美元为边界。

实际接入曾出现 HTTP 400：Sol 的 Chat Completions 不支持同时开启推理与 function tools。此前只验证简单 JSON 生成，没有验证完整研究链，是验收范围不足。现在官方 OpenAI 地址的所有模型请求统一使用 Responses，旧 Chat Completions 仅留作兼容其他服务的路径。

最终真实 Responses 测试 `TestLiveFirstReplyThenResearch` 通过：

- 15.37 秒：首句给出“远距型偏低阻和动量保持，稳定型偏自稳和容错”的初步观点，并已安排后台工作。
- 累计 43.21 秒：使用深入推理完成分析并保存《纸飞机远距型与稳定型：设计取舍短草稿》。
- 累计 55.22 秒：把已保存的结果分享回群，明确是原理分析、没有实体试飞。

这些是本机、当前代理和一个样例的观察值，不是秒回承诺或统计性能指标。模型输出仍经过发布核对，没有把未核对的生成文本逐 token 展示。普通闲聊也不会强制安排研究。

新增自动检查覆盖首句不能提前执行慢工具、并发请求推理配置独立，以及 Responses 工具往返保留加密推理项目和正确的 call_id。测试证据在 `test-results/openai-responses-pacing.txt`。

完整技术选型复查见 [接入与依赖审查](integration-audit.md)。


## 2026-11-06 晚间体验回归

用户实际使用暴露了此前验收遗漏：必答多题入门、群聊在第一位安排研究后提前结束、Responses 加密内容触发 180KB 内部限制、空会话没有自主机会、详情弹框过多。完整根因、产品对照和新验收见 [体验复查](experience-audit.md)。

创建现在只需要名字和头像，单题偏好可跳过；详情改为非模态侧栏。后台补齐其他成员的参与机会、长工具结果的原文回读、可见的成员行动及参与判断、空会话自主探索，以及研究收尾时保存成果的机会。原有 24 个离线用例加上 8 个回归，共 32 个通过 race 检查。

真实独立服务验收观察到：关闭浏览器且群内无人类消息时，两位成员自然先后发言；随后一条研究请求在 18.92 秒发出首句，经历超过旧故障规模的工具行动后完成资料解释。验收进一步发现未及时保存笔记，修正收尾阶段后恢复同一任务，真正保存并分享了 1,031 字符的成果。没有将第一次只有聊天解释的结果算作完整成功。
