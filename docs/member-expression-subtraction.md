# 成员表达与执行隔离：减法记录

2026-11-07。

## 已确认的问题

- 群聊共用的执行循环从第一版开始会在某位成员行动失败时返回，后面的参与者没有机会执行。`1a43d5b` 又把网页工具的请求错误向外传播；因此一篇网页返回 404 就可能中断全群。
- 成员已返回完整聊天正文时，旧程序仍要求按 JSON 解析，格式不合就不发布；恢复还可能重复消费同一份无法解析的响应。
- 每条消息、私聊、作品和记忆都经过额外模型审核，审核可改写或拦截原文。公共提示与记忆维护说明也叠加了统一的表达规范。
- 原群的 guidance 保存了控制模型自行补写的核实、事实/推测区分等要求，冒充成共同的用户方向。仅删除源码提示不会删除这份已保存内容。

## 本次删除与修正

- 删除 `reviewText` 与所有 Review 调用，内容不经过另一个模型统一改口。
- 精简成员、状态、记忆、协调和工具说明；不规定严谨程度、立场、表达情绪或附加免责声明。记忆记录不再是完成参与判断的前提。
- 控制模型的 guidance 只记录真人明确方向，不能自行加入表达或核实要求；新建人设不再附加“不虚构过往经历”的共同尾注。
- 网页读取等普通工具失败作为工具结果交回本人，可继续发言或选择其他行动。预算、取消及数据归属仍保留原有真实语义。
- 模型请求/输出失败留在对应成员的记录，其他已决定参与者继续执行。已有 SQLite 现场按成员恢复，不增加人格状态机或整群自动重试。
- JSON 请求正确声明输出协议；旧现场的普通正文直接保留。无效的可选引用只去掉引用，不取消发言。恢复时更新公共提示和当前上下文，避免旧断点重新带回已删除要求。

## 验证

`member_independence_test.go` 验证真实 HTTP 404 后本人继续表达、成员失败后同伴继续、恢复不重复发布、旧正文不被审核改写、成果原文保存。既有记忆来源、版本更正与成员归属测试仍执行。

真实模型使用正式数据库的独立副本 `data/chat-subtraction-acceptance/`，没有向正式群发送验收消息。原来的“其他人就没有自己的想法吗？”工作恢复后，裴船已保存的正文得到发布，青雉也随后回应。原始稿不重写；新回复仍出现保留措辞，不能据此宣称自然度已经达到要求。

中间验收发现 JSON 模式要求提示中包含 JSON 字样；参与提示补上协议声明后再验。测试报告和未通过的尝试留在独立验收目录及 `/tmp/dropby-natural-live.log`。新群对照使用相同成员，结果另存 `fresh-*.json`。
