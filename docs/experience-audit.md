# drop_by 体验复查：创建、群聊与主动性

日期：2026-11-06。依据用户本次实际使用反馈，并在本机服务复查。比较对象为 Grok Bot 与 Meta Muse。此次方向经用户确认：清爽中性色、聊天为主、统一右侧详情栏。

## 证据范围

- 自有产品：读取实际失败会话、工作与工具记录，查看当前浏览器界面，再用隔离的 `data/ux-acceptance/` 跑真实模型和浏览器流程。没有把测试成员混入正式聊天。
- Grok Bot：查看官方创建、群聊、后台例行工作文档，并检查 `x.ai/bot` 的公开界面演示。未登录其完整产品，不能声称实测了付费账户内的执行质量。
- Meta Muse：核对官方产品说明。没有登录实测其个人账户工作流；下述能力是其官方描述。
- 所有本地截图都在本轮生成并打开检查；旧截图只用于同一次复查的改前对照。截图保存在 Git 忽略目录 `output/playwright/`，不作为远端仓库自带资源。

## 实际问题和原因

| 用户遇到的现象 | 实际证据与判断 | 修正 |
| --- | --- | --- |
| 创建像做问卷 | 界面先要求方向，再同时呈现多题；后端要求至少两题且全部回答 | 名字和头像直接创建，无模型调用；偏好放到相识后自愿补充，一次一题，可跳过 |
| “正在看看”不知道是谁 | 前端只检查群是否存在运行任务，未拿到具体执行者 | 成员姓名加实际动作；只在真实调用期间显示，结束或取消后移除 |
| 第一句就提示上下文太长 | 实际首条真人消息只有 19 个字；后续研究连续执行 17 次搜索/读取。旧代码用序列化请求超过 180KB 判断“上下文过长”，把 Responses 加密推理传输体积也计了进去 | 保留推理与工具协议项目；工具正文按新旧摘录，完整返回保存在 SQLite，可按 ID 分段读取；传输异常限制与模型上下文分开，预算不按加密 Base64 字节计费 |
| 两人群只有一个人响应 | 第一人用工具安排研究后，整个交流机会提前返回；其他人此前即使想参与，也没有后续机会。旧版本未保存各人的参与理由，无法倒推另一个人当时具体为何安静 | 去掉提前退出；每次独立判断仍可参与或安静，保存参与理由及是否获得行动机会，避免把调度故障归因给性格 |
| 后续研究被安排两次 | 工具显式安排研究后，`unfinished=true` 又创建另一项延续工作 | 已成功安排研究时不再因 unfinished 重复安排 |
| 积极成员在无人发话时没有动静 | 有后台定时器，但空会话被排除；任意未来 pending 研究会挡住全群的新探索。原默认判断间隔 30 分钟 | 新聊天一分钟后获得第一次自主机会，之后默认每 10 分钟判断；尚未到期的研究不阻塞其他探索，暂停及预算边界继续生效 |
| 弹框打断交流 | 创建、资料、成果、工具记录都使用同一阻断式 dialog，并带模糊遮罩 | 桌面统一非模态右侧详情栏，聊天始终可用；手机为有明确关闭入口的详情页；控制台式原始记录默认折叠 |

这些属于已确认的实现问题。不能以“成员性格内向”解释缺失的执行机会，也不能把内部请求膨胀归咎于用户第一句话。

## 与参考产品的具体差距

| 体验维度 | 参考依据 | drop_by 的决定 |
| --- | --- | --- |
| 低成本相识 | [Grok Bot 创建说明](https://docs.x.ai/grok-bot/bots)：名称和头像样式后直接聊天，长期要求在对话中补充 | 移除创建问卷。一次一题且可跳过按用户明确要求实现，不把它包装成未经核实的 Grok 全局规则 |
| 行动归属和可见交接 | [Grok Bot 消息与协作](https://docs.x.ai/grok-bot/chat-and-collaboration)：聊天包含行动和结果；普通群消息由各 Bot 决定回应，@ 用于明确指定对象 | 给具体成员标注行动，补齐参与机会；保持自主发言，不做强制全员轮答 |
| 离开之后仍推进 | [Grok Bot routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)：明确执行者与触发方式，云端运行；[Meta Muse 介绍](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)：关闭应用后继续目标，在有变化或需批准时回来 | 修复本机服务的无新消息探索和未来任务阻塞；说明“浏览器关闭”和“电脑休眠”是不同边界。没有擅自扩展为云端部署 |
| 可理解的持续工作 | Muse 官方说明强调可查看已做与计划做的行动 | 将任务状态、工具记录、成员参与理由放进动态详情，失败保留进展并可带回聊天继续 |
| 朋友群的定位 | 上述产品侧重任务协作；原需求还包括闲聊、不同兴趣与持续关系 | 借鉴轻入口、可见行动和异步推进，不把每次交流都变成工单，不把固定发消息频率当作主动性 |

## 本轮验收

### 确定性回归

在既有测试外增加八个顶层用例，覆盖：

1. 无 @ 的双成员场景，第一人安排研究后第二人接话；只产生一份后续研究。
2. 没有真人消息、没有浏览器的空群仍获得探索机会；明天的研究不阻塞今天。
3. 每秒轮询不会堆积探索；等待预算、明确停止研究继续生效。
4. 17 份长网页结果压缩后保留工具 ID、近期正文与旧摘录，重复收缩幂等，原文可分段找回且不能跨群读取。
5. 超过 180KB 的加密推理项目能完整回传 Responses，不会当作巨量用户输入误扣预算。
6. 名字即可创建；跳过不调用模型；自愿补充偏好不改变成员 ID、创建日期和私聊关联。
7. 正常小 PNG 可以保存，远程地址、SVG 和无效头像被拒绝。
8. 研究快用完工具往返时，仍能真正保存用户要求的笔记，再交代结果。

模型替身用于复现执行边界，不能证明长期行为自然度。

### 浏览器和真实模型

- 在浏览器中只填名字创建阿苇，直接进入私聊；当时应用费用账本仍为零次调用。
- 手动打开可选偏好，只显示一个问题和“跳过，去聊天”；点击跳过后资料未改变。
- 22:49:44 关闭验收浏览器。新测试群没有任何真人消息；22:49:55 乔主动分享纸飞机观察，22:50:07 阿苇接话补充记录方法。此后两人均自主选择暂停补充，均有记录。证明该次机会不依赖浏览器或真人消息，不代表每次机会都必须发言。

## 尚未解决或不能由本轮证明的部分

- 本机服务必须运行；电脑休眠、关机时不执行，没有云端驻留或自动启动。
- 浏览器通知依赖打开的页面；关闭整个浏览器后的系统推送尚未实现，重新打开会读到持久化消息。
- 成员长期兴趣是否稳定而有变化、主动内容是否值得收到、多人相互影响是否自然，仍需真实使用评估。两人成功接话不等于“群已像朋友一样自然”。
- 首句仍要经过实际模型生成与核对。本轮会记录实测耗时，不称作“秒回”。
- 提供新研究机会不会保证每人开口；动态中的参与理由用于区分主动选择安静、等待执行与运行失败。

## 最终真实执行记录

真实使用 OpenAI Responses（`gpt-5.6-sol`）与 DeepSeek Search/Fetch，未将密钥写入代码。新创建的测试成员和群保存在独立目录。

- 原测试群只有两位成员的自主交流。随后发送一条合成请求：查找两份靠谱资料，解释纸飞机抬头后下坠，并保存短笔记；没有 @。
- 首句实际耗时 **18.92 秒**。研究首轮完成 **21 次工具行动**（含搜索、读取与安排），没有再发生旧的内部上下文错误；有网页返回 404/504，记录为失败，没有伪造读取成功。
- **265.06 秒**时分享了带来源的解释，但该轮没有保存独立成果。这是验收失败项，而不是将聊天文字算作成果；据此增加了研究收尾的保存机会，并让真人请求的未完工作及时接续。
- 更新后二次执行复用同一个未完工作，没有新增真人消息；仅在隔离验收数据库把旧版本安排在十分钟后的 due_at 提前，模拟到期，不修改正式数据的任务时间。实际通过 `read_tool_result` 找回之前的完整材料。
- **23:01:12** 保存《纸飞机为何会突然抬头后下坠｜短笔记》第 1 版（1,031 字符），**23:01:34** 回群分享成果。最终研究和分享均为 done，没有遗留本次研究的待执行项。验收账本累计估算 **$1.156**，包含创建后的自主交流、偏好题、研究、恢复和核对；它不是服务商账单。
- 桌面检查了创建、单题跳过、聊天可同时操作的动态详情；390×844 检查了聊天与详情页面。活动刷新曾打断平滑滚动、使视图停在历史中间，改为即时定位，并在最终页面重新核验。
- 浏览器控制台的 SSE 断流出现在主动重启服务时，页面随后自动重连；没有把这种预期断流报告为完全无错误。最终运行时另行检查脚本错误和布局。

本轮验证命令为 `go test -race ./...`（32 个离线顶层用例通过，2 个原有 opt-in 真实测试默认跳过）、`go vet ./...`、`go build`、`node --check`、`git diff --check`。此次真实验收通过独立服务和浏览器进行，不能把 opt-in 测试的跳过算作通过。

正式服务已在 `127.0.0.1:8090` 更新并实际打开检查。切换前创建了本地 SQLite 备份；原有 2 位成员、3 个聊天以及 9 条历史消息逐条原文比对通过，未改写旧消息。日预算保持 $3，新默认探索间隔为 10 分钟。
