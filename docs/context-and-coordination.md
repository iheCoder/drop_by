# 上下文、群协调与周预算（2026-11-07）

这次沿用已有 SQLite、成员身份和工作队列，改进角色如何记得、怎样把工作交给同伴，以及费用的时间范围。没有换模型、引入独立 Agent 框架或数值化人格。

## 设计依据

- [Anthropic: Effective context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)：固定核心信息、用轻量引用按需取回材料，先清理冗余工具正文，保留关键决定和未解决事项。
- [Letta Memory](https://docs.letta.com/agent-sdk/memory)：核心与外部记忆分开，外部内容按需读。借鉴边界，不迁移到其运行时。
- [Generative Agents](https://arxiv.org/abs/2304.03442)：行为受经历、检索与持续关注影响。这里继续使用自然语言笔记，不复制相关性或重要性数值打分。
- [OpenAI Agents SDK orchestration](https://openai.github.io/openai-agents-python/multi_agent/)：管理者委托与主动权转交是不同模式。本项目给协调者工作委托权，成员仍拥有自己的判断与表达。
- [Anthropic multi-agent research system](https://www.anthropic.com/research/multi-agent-research-system)：委托要讲清目标、预期结果、边界；额外 Agent 有成本，所以不强制所有聊天变成分工。

这些是设计参考，不代表相同实现或论文效果已在本项目复现。

## 上下文与记忆

- 人物说明、有效用户方向、当前自然语言状态及当前触发工作保留。未完成工作独立查询，不再被最近已完成的工作挤出；优先自己的工作，最多带32条简短索引，其余可翻页读取。
- 默认近期入口最多16条、合计约10000字符，长消息摘录保留头尾。当前任务的原始触发消息单独读取，即使已经很早，也不会依赖近期窗口碰巧包含它。
- 每名成员可在正常参与判断或行动输出中给出 `context_start_id`：自己确认旧话题不再有用后，后续默认窗口从该消息开始。可保留或清除这个选择，不新增机械话题分类，也不删除原文。重要持续内容由 `state` 或 `remember` 留下；是否正确判断重要性仍依赖模型。
- 最近记忆只提供6条短索引；`search_memory` 支持本地中文原词、多词任一匹配、浏览与游标翻页，`read_memory` 读完整笔记。这不是向量语义检索；模型可以换词搜索，检索不到时不能声称没有发生过。
- `read_history` 可搜索、翻页或按消息ID分段读取原话。`read_artifact` 可按标题发现旧作品、翻页，再按ID读版本。作品默认只带元数据，不重复塞 HTML 源码头部。
- 决定 speak / explore / revisit / pass 之前即可本地回忆、整理经历。此阶段不能联网、发消息或委托；即使查完选择安静也正常。首次回应可读本地旧材料，联网与创作仍交给后台。
- 参与判断和实际行动共用同一成员的执行锁，防止跨群同时改写可携带经历。个人记忆工具日志及二次 `read_tool_result` 日志只对本人进入模型上下文；用户仍可在UI审计记录。当前群网页、成果和工作记录可以共享。该隔离不等于模型自动识别敏感内容已有绝对保证。
- 完整模型请求有统一容量保护，默认输入保守上界加输出预留总量100000。估算包含系统说明、工具定义与协议开销，优先折叠可回读的工具正文；不裁掉身份、目标或调用ID，不把加密 reasoning 的编码字节误当成 token。仍过大的固定内容会在请求/扣预留之前报告实际原因。这不是精确 tokenizer，也不是供应商上下文窗口的声明。

## 群内协调

在聊天标题打开的群详情中选择“群里的协调者”，可选任意本群成员，也可恢复“各自参与”。私聊没有此设置。职责仅属于这个群，不改人物资料。

`delegate_work` 只对当前协调者开放：指定同群另一成员、具体任务与结果边界、选择理由。接收者继续使用自己的身份和工具，可以说明不适合、已无必要或实际阻碍。已安排的同项工作不会重复插入；每个执行根最多6次协调委托，保留同一根与费用来源。

复用 `research` 执行任务；真实完成、失败或暂停后产生持久的一次 `revisit` 给当前协调者。协调者可 `read_work` 查看结果，推进下一位或安静结束，不额外轮询催促。成果归实际制作的人，分享仍是其自己的判断。更换协调者会移交尚未处理的回报，取消角色会撤下回报机会，不取消同伴已经接手的研究。

普通职责变化和人物资料变化使用不同重试依据：换协调者不能吞掉尚未理解的真人偏好；后来手动修改的人物说明也不能被旧消息或预算重试覆盖。

## 定时与预算

`schedule_followup` 支持相对延时和带时区的 RFC3339 绝对时刻（如明早九点）；两种时间参数不能同时填写。是一次重新考虑的机会，不是固定群发。它会保存在 SQLite，重启后恢复，可以取消。服务停止或电脑休眠时不能准点运行；目前没有周期 cron。

总预算每周20美元，其中自主工作子上限7美元，调用上限4200。按服务进程本地时区周一00:00重置，部署使用 `TZ=Asia/Shanghai`。原来的每日账本保留，本周已有消费直接累计；不清零、不伪装服务商余额。错误分别说明真实耗尽、余额不足以预留、调用次数到顶、自主额度不足。启动后重新核对旧预算等待，预留检查仍不可绕过。

旧环境变量需迁移：`DROPBY_WEEKLY_BUDGET_USD`、`DROPBY_WEEKLY_CALLS`、`DROPBY_AUTONOMOUS_WEEKLY_BUDGET_USD`。新值显式提供时可覆盖残留旧变量；只提供旧日变量会提示迁移，不把旧3美元默认为一周3美元。

## 实际验证

最终自动回归报告：`test-results/context-coordination-final.json`。91个顶层测试通过，含子测试共112项通过，5个显式真实服务测试默认跳过；`go test -race`、`go vet`、JS语法和构建均通过。覆盖记忆/历史/作品发现与分页、模型选择话题窗口、身份和旧目标保留、参与前检索后安静、私聊文案、绝对定时、整请求压缩与 Responses 协议、周界和并发预算、协调权限/幂等/接力/换人及资料更新竞态。受控模型测试不能证明真实角色长期自然度。

真实模型使用独立目录 `data/context-coordination-acceptance`，不向正式聊天写测试内容。模型仍为 `gpt-5.6-sol`，深入推理high；验收小卡片单独限制快速输出2000、深入输出8000、总预留上限1.10美元。

第一轮暴露了无必填工具的 `required:null` schema 错误，已改为 `[]` 并加回归；失败证据保留在 `first-schema-failure.json`。修复后真实验收82.20秒通过：阿岚实际使用 `search_memory` / `read_history` 找回窗口外旧约，把深蓝与暖白、没有倒计时等要求交给小芽；小芽保存3337字符HTML《星灯卡》；完成事件触发阿岚读取工作结果并完成复看。成功这轮20次调用、应用估算增量0.644224美元；目录累计23次、0.894344美元包括首轮失败的保守预留，不等于服务商账单。记录在 `context-coordination-report.json` 和 `test-results/context-coordination-live-retry.log`。

真实消息：小芽分享“只用深蓝与暖白，按钮可切换短句，没有倒计时或外部资源”；阿岚回应“收到，小芽做得正合旧约定……就这样轻巧收灯”。这证明本例的检索、委托、制作和回报链路成立，不把单个样本当成长时间人格一致性的证明。
