# 2026-11-07 模型选择与 Responses 接入

## 当前选择

采用一版简单分工：参与判断和相关经历检索使用 `gpt-6-luna`；日常发言及普通后续接话使用 `gpt-6.1-terra`；实际研究、控制理解与真实性核对使用 `gpt-6.1-sol`。不增加统一裁判、自动模型分类、旧型号回退或工具链重放。

Luna、Terra 的普通调用使用 `none`；Sol 普通调用使用 `low`，实际研究使用 `high`。这些是当前本地网关实测可接受的参数，不代表所有提供商都支持同样的组合。每位朋友保留原来的身份、上下文和工具权限，模型职责不改变人格资料。

压缩继续使用**当前调用模型**的原生计数、压缩、续接接口，不能把不透明的加密推理或压缩记录任意转给另一模型。没有另加一套普通摘要来替代原生压缩。

这是项目适配选择，不是模型通用能力排名；没有因为样本少就推断某个模型绝对更好、更便宜。

## 已做了什么，为什么不再扩大实验

初始批次在用户收紧范围前已经完成：9 个场景，每个模型两次，含旧基线共 72 个场景执行。用户明确排除旧型号后，不再将旧基线用于选型，也没有继续执行新增场景矩阵。三个候选对应的 54 份结果保留供复核；后续只检查实际组合与接口兼容。

所有输入、角色和历史均为合成测试数据，每次执行使用独立 SQLite。使用生产参与判断、工具权限、实际工具记录、成果保存和核对代码；没有向正式聊天发送测试消息，没有联网搜索。生产提示词、请求正文、模型名称、推理配置、工具结果和返回用量均在本地结果文件中保留。未保存请求头和凭据。

初始样本的普通调用沿用了原路径：Luna/Terra 普通调用走 Chat Completions，深入任务和 Sol 使用 Responses。后续统一改成 Responses 后，用真实组合链路验证了三模型及工具续接。因此初始延迟仅供观察，不能当成最终协议配置的性能保证。

## 场景与实际表现

| 场景 | 期待的用户结果 | 三个候选的实际观察 |
| --- | --- | --- |
| 用户说先聊到这里，不回复、不安排后续 | 成员可沉默，不制造待办 | 都选择 pass，无新增后台工作 |
| 旧约定埋在近期窗口之外 | 先找原话，不能凭空猜记忆 | 都实际检索到“深蓝、暖白、不要倒计时” |
| 雨天闲聊、给活动取名 | 简短自然地接话，无强制组织流程 | 都生成具体短句，无新增后台工作；自然度仅作文本判断 |
| 新证据改变浏览器选择 | 能改意，同时保留保存期限未知 | 都调整原选择，没有补出材料未说明的期限 |
| 核对虚构搜索、试用、委托、保存 | 不把意图或身体经历说成事实 | 都纠正了无依据的完成声明 |
| 核对主观名字与玩笑 | 不把合法主观表达改成套话 | 都逐字保留给定文本 |
| 制作小 HTML 卡并保存 | 形成真实成果，不预约无关后续 | 都实际调用 save_artifact 并形成 HTML 版本；未做作品浏览器验收 |
| 原生压缩后继续回答 | 保留已存成果 ID、版本和禁用功能 | 都返回原生 compaction，并正确保留关键字段；Luna 有一次额外附带自相矛盾的“不确定目标 ID”说明 |

**参与判断选择 Luna：** 在“还记得星灯卡约定吗”的场景，它实际调用 `read_history` 后准确找回原话。该场景和停聊场景合计四次执行，中位耗时约 2.21 秒；Terra 约 5.10 秒，Sol 约 4.60 秒。这个结果支持先用 Luna 做参与与检索，不证明复杂关系判断已充分验证。

**日常回应选择 Terra：** 它对取名给出“雨滴摸鱼局：雨负责下，我们负责慢一点”，对新证据改口给出明确选择，并保留“材料没说保存期限”的边界。三种聊天场景共六次执行中位耗时约 4.24 秒；Luna 约 3.88 秒，Sol 约 5.67 秒。选择 Terra 是结合短句表现与职责定位的第一版取舍，不是断言它在角色感上统计显著领先。

**研究与核对选择 Sol：** 实际制作任务能调用工具、保存成果并正确给出证据；核对能区分虚构身体经历与工具完成记录。三个候选都完成了这个小任务，不能据此宣称 Sol 在复杂研究上胜出。依照已讨论的职责定位，先让 Sol 负责这些步骤，不为少量辅助调用进一步拆出更多模型配置。

初始三个候选合计报告输入约 49.47 万 tokens、输出约 2.19 万 tokens。记录的是供应商返回用量，不是账单；网关价格、缓存折扣未验证，不用项目中统一的预算折算费率宣布“节省了多少成本”。

## 新接口适配与组合检查

所有模型调用现统一采用 `/responses`，包括普通聊天。使用 `max_output_tokens`、`reasoning.effort`、`text.format`，原生 `function_call` / `function_call_output` 和推理项目完整续接，`store=false`。只保留这一条生成接口，移除旧型号前缀识别、Chat Completions 请求构造和旧响应结构转换；失败不会自动降级。

组合场景是“先说一句纸飞机距离与稳定性的初步想法，再比较两种设计并保存短草稿；不联网、不假称实体实验”。第一次运行暴露了接口解析错误：Luna 的同一 Responses 返回同时含 `commentary` 与 `final_answer`，旧代码拼接两段，破坏了最终 JSON。修复后只读取最终阶段的文本，同时原样保留所有项目供续接；确定性回归测试覆盖这个真实响应形状。

修复后的实际轨迹使用了三个选定模型，18 个请求全部通过 Responses 返回 HTTP 200。Luna 判断参与并读取本地记录；Terra 发言，在后续机会实际调用 save_artifact 保存短稿；Sol 核对记忆、正文和成果。最终聊天带有成功保存记录的 evidence，SQLite 中存在对应成果。

旧的真实测试要求“必须出现后台 research”，因此进程输出仍报告该断言失败。但这个场景已直接完成并分享成果，属于允许的轻量路径。按用户要求不强制所有工作进入研究，验收改为接受“实际研究接力”或“直接保存并凭成功记录分享”两种路径。对已保存轨迹做了独立结果核查，所有条件通过；未为了让日志变绿再发一批真实模型请求。原失败日志保留，不改写历史证据。

组合也暴露出 Luna 在某次参与理由中提前声称“已保存”，当时实际尚未保存。后续发布和成果归属仍由实际工具记录与 Sol 核对约束。这提醒我们不能把参与意图、理由文字作为完成状态；长期人物连续性和类似过早自述仍需使用中观察。

## 检查范围与限制

| 检查角度 | 状态 | 本轮依据与缺口 |
| --- | --- | --- |
| 业务规则 | 部分覆盖 | 停聊、原话检索、证据边界和保存结果已检查；长线关系与人格自然度未充分验证 |
| 状态变化 | 已覆盖（本轮范围） | 真实工具记录、成果保存与公开证据链接；不把安排和意图当作完成 |
| 输入与边界 | 部分覆盖 | 闲聊、旧约、新证据、虚构完成与长输入；未覆盖完整任务分布 |
| 外部依赖 | 部分覆盖 | 当前网关真实 Responses、原生压缩和 SQLite；未做外网搜索与网关故障恢复实验 |
| 时间与并发 | 部分覆盖 | 确定性并发测试验证请求间模型/推理配置不串线；未做压力或长时延测试 |
| 兼容与回归 | 已覆盖（本轮改动） | 新模型参数、阶段解析、原生工具续接及现有 Go 回归；未复验所有历史真实模型场景 |

不新增自动重试或跨模型重跑任务，不更换 UI。代码与测试不证明真实网页资料准确性、复杂研究的全面优劣，也不证明模型永远不会出错。

## 复核与复现

- 初始记录：`test-results/model-selection/20261107-144423/`，每次执行包含 `result.json` 与独立数据库。
- 首次组合错误：`test-results/model-selection/selected-responses/`。
- 修复后真实轨迹与结果核查：`test-results/model-selection/selected-responses-fixed/`，其中 `outcome-checks.json` 是独立结果校验，`run.log` 保留原断言失败。
- `TestLiveModelSelection` 默认已收窄为三个候选、三个场景、一次执行，默认跳过；必须显式启用并指定新目录，避免重复运行污染结果。
- `TestLiveFirstReplyThenResearch` 是组合验收入口；`DROPBY_PACING_REPORT` 可保存正文轨迹。密钥只从运行环境读取。

接口依据：[Responses 迁移指南](https://developers.openai.com/api/docs/guides/migrate-to-responses)、[推理模型与原生续接](https://developers.openai.com/api/docs/guides/reasoning)。本地模型名与参数是否可用，以本轮真实网关返回为证据。
