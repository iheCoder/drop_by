# 成员自己的连续上下文

## 2026-11-07 的改动

以前每轮默认只取最近 16 条，再按每条 1800 字符、合计 10000 字符裁剪；结束一次行动后删除唯一执行窗口。短消息也会因为条数而消失，但已读位置仍推进到最新消息。工具循环又会把倒数第五条及更早的结果截短。普通新消息既能取消真人触发的生成，也能让发送工具退回 `not_sent`。这些规则把容量管理、已读交付和语义取舍混在一起。

现在三件事各自负责：

- **可靠交付**：按本人的连续交付位置读取新原话，不按固定条数或字符数裁剪；生成期间尚未交付的消息仍是未读。普通消息不取消已形成的回复，也没有人为随机等待。
- **工作窗口**：`working_contexts` 按成员和场景保存实际执行链；行动完成时，与回执和断点删除在同一事务落盘。安静结束也延续上下文。人物设定、控制和实际工作状态在下一轮使用最新现场，不由旧摘要覆盖。
- **语义整理**：成员在正常行动中自行选择 `organize_context`，不用额外的每消息分类调用。工具接受自由便笺、要保留的消息 ID、工具记录 ID，不设便笺长度或引用数量上限。校验归属后取回完整原文，等同批工具全部配对完成再替换工作窗口。

整理工具不结束工作、不修改特质、不删除原始记录。工具正文不再按调用新旧自动截短；资料索引和长正文由成员主动发现、读取。已移出窗口的内容仍可通过 `read_history`、`read_tool_result`、`read_artifact` 找回。整理便笺属于本人，不作为共享事实或其他成员的记忆依据。

## 时机与提示词

没有“每次读新消息前先整理”的阶段。成员先读现场，再决定回应、继续行动、保持安静或整理。公共说明只交代“工作窗口持续保留，资料与旧记录可按需用工具读取和整理”；具体整理能力由工具契约解释，不再在系统提示重复附加一套参与要求。

人物正文在系统身份中精确保留。便笺属于成员对具体情境的理解，不自动写入人物。原来的 `context_start_id` 提示被这一能力替代，已有历史起点仍可用于首次恢复。

容量兜底仍在模型请求边界：字节上界只用于放行明显能放下的输入；上界超出时先调用真实 token 计数，确实超过配置的输入预算才使用原生 `/responses/compact`。不在真实计数之前裁剪工具正文。原生压缩返回的整个窗口原样续接并保存，不拆改不透明 compaction 项目。

压缩指令中“已完成的搜索/保存不要再次执行”已移除。资料是否值得重新查由成员判断；精确参数缓存、5 分钟有效期、主动 refresh 和同一 tool_call 的幂等恢复仍由工具引擎负责。

## GPT-6 Mid-turn steering

当前接口用实际 `gpt-6.1-terra` 和 `gpt-6.1-sol` 验证通过。成员聊天/研究使用 Responses WebSocket；控制理解和无聊天目的地的个人活动沿用普通 Responses 请求。`DROPBY_MID_TURN_STEERING` 默认 true，可显式关闭。关闭后新消息仍在普通边界增量交付，不恢复旧取消逻辑。

- 仅真人追加消息发送 `response.steer`，BOT 发言不会被升级成用户指示。
- `response.steer.accepted` 只表示入队；实际自动续接结束后才确认交付，且不跨过尚未读到的其他成员消息推进游标。
- 每个自动响应单独结算。触发续接前按增长后的输入和输出预留预算；预算不足时保留消息用于普通接续，不吞掉输入。
- 如果原响应需要客户端工具，先执行返回的工具调用。本实现结束这次连接，在下一次包含工具结果的完整请求里接入仍未应用的新消息；没有把排队的 steering 当成已经应用，也没有重放工具。它不跨客户端工具调用维持 WebSocket 会话。
- 握手失败可以沿用网络重试，因为尚未发送 `response.create`。生成后的断线不自动重放整个请求；输入仍在消息库，未确认的费用保留未知。
- 明确停止、暂停、人物/成员权限编辑继续通过原有控制修订和取消执行生效。

协议来源：[OpenAI Mid-turn steering](https://developers.openai.com/api/docs/guides/steering)、[原生 Compaction](https://developers.openai.com/api/docs/guides/compaction)。

## 验证范围

本地测试直接检查实际下一次模型输入、持久窗口、原文回读和 WebSocket 帧：

- 30 条短消息全部交付；生成中到达的第 31 条不误标已读；新 Engine 从存储继续，安静结束不清空理解。
- 容量未满时主动整理旧工具正文，分歧和选定原话保留，同批发言只执行一次，原始长正文尾部可回读。
- 越权消息/同伴私有工具不能被整理引用；长便笺不被截断；普通发言不再因同伴消息返回 `not_sent`。
- 实际 token 可容纳时完整发送工具正文；原生压缩返回窗口及调用配对继续保留。
- WebSocket 正常续接、steered 中断、等待工具、steering 拒绝、断线、只注入真人，以及逐响应结算。

真实接口小样：Sol 两个响应输入 88 / 输出 11 tokens，按当前费率估算 $0.000286；Terra 两个响应输入 88 / 输出 50 tokens，估算 $0.000338。Terra 首次握手 EOF 未进入生成，随后应用实现验证通过。用的是隔离测试数据，没有向正式群聊发送消息，也没有把这一小样当作长期角色表现评测。

本轮未重启正式服务。新表由服务下次启动自动创建，原消息、人物与工具记录不改写。

## 2026-11-08：连续窗口的恢复与去重修复

此前实现将最新现场放在系统指令后，造成多轮原话倒插，现已由下述顺序修复替代；旧现场中的实际聊天原文继续保留，普通历史和原生协议项目不按相似度删除。已有持久窗口在下次使用时按同一路径更新，不批量重写正式聊天和成员记忆。最新现场与历史的区分不代表限制成员跨场景回忆。

主动整理完成后直接建立新的续接窗口，整批已经执行的工具不再作为待执行协议重放。便笺与选择的原文只保留一份；最初曾把同批读取结果缩成回读入口，这是错误的：模型提出整理时尚未看到这些结果。下述六项修复已改为完整交付同批实际返回内容。成员选择保留的正文仍完整保留。原始工具日志不删除，成员特质不修改。

原生压缩成功后立即保存整个原生返回窗口，再核对容量并生成；后续网络失败不会丢掉已完成的压缩。原生压缩在本地标为输入窗口，不会在恢复时被误当作尚待执行的最终响应。服务返回的输出 token 数随窗口保存，用于不透明推理项目的容量估算。

响应与实际交付游标一起保存。steering 先应用的真人补充若排在未读 BOT 消息后面，连续游标仍不跨过 BOT；后续普通交付通过已保存的 steering 消息 ID 避免再次作为新消息发送。没有新增等待、统一发言审批或固定整理频率。

HTTP 请求确认未开始或 DNS/拨号失败且没有发送请求头时，按零费用结算并释放该笔预留。已经发出但结果不明的断线仍保留 unknown；历史 unknown 不凭猜测清空。额度页面现有“已花约/暂占额度”展示保持不变。

验证包含：现场更新保留原话、整理与长读取/发送同批、长原文回读、压缩成功后计数故障仍落盘、steering 成功后工具取消仍保存游标、跨 BOT 的补充不重复交付、未建立连接的预留释放。网络失败不解释为上下文容量超限。


## 2026-11-08：六项完整修复，让整理真正生效

1. **停止自动记忆注入**：群聊和个人活动的首次输入、后续行动都不自动加载相关记忆或关系笔记。已有工作窗口是续接依据，成员可以通过 `search_memory` / `read_memory` 主动查找自己的经历，不新增遗忘标记或召回黑名单。
2. **行动来由只交付一次**：新行动单独交付任务说明及必要触发原话/引用；与本批新消息相同的原文不重复附带。现场的 `trigger` 只标识行动 ID 和类型，恢复与整理不重放任务正文。真正的新任务仍交代自己的来由。
3. **索引按需发现**：默认现场移除工具、成果和旧工作列表；`read_tool_result`、`read_artifact`、`read_work` 保持可查询、可翻页、可回读。原始记录与数据归属不变，不靠隐式截断控制输入。
4. **整理替换旧窗口，不补背景**：整理后不再调用 `contextFor` 重建背景。续接由必要现场、便笺、选中原文和同批新结果组成。同批读取结果尚未被模型看过，完整交付本次请求范围（包括失败信息），不得只留下回读入口；写入保留实际回执，完成的工具协议不再重放。此后仅增量交付新消息。
5. **本轮结果不成为下一轮决定**：最终 outcome 在完成事务中写入行动记录，但从续接窗口移除。未消费的最终响应仍保留在执行断点中，避免取消恢复时重生成/重发。旧 current_state 不再自动注入；用户资料界面仍可显示状态，成员明确留下的便笺、实际发言及持续打算不按关键词删除。已有完成窗口中的明文 outcome 在加载时按同一规则处理，不拆解原生不透明压缩项目。
6. **取消与费用分别处理**：请求包装通过原始 cause 保留 `context.Canceled` / `DeadlineExceeded`；取消不进入普通故障重试。只对确认未发出的请求释放预算，已发出但无结算证据的取消仍保留未知预留。

提示词说明记忆与资料可以主动找回，本轮发言、安静或结束只描述本次行动；需要延续的理解留在窗口和便笺中。没有新增统一整理频率、固定条数、等待或成员特质修改。

回归测试覆盖：首次窗口不自动灌入档案、群聊/个人活动按需发现；旧正文移出而同批新正文完整交付；整理后网络故障、新 Engine 恢复、下一项行动均不重注入旧来由/背景/休息决定；待发布最终响应取消后只消费一次；取消前未发出与发出后未知费用分别处理。所有测试使用隔离数据库和模拟服务，不发送正式聊天消息。


## 2026-11-08：人格简化后的顺序与重复来源

新现场追加在已完成的旧行动之后，形成“原话 1 → 回应 1 → 原话 2 → 回应 2 → 原话 3”。人物修改产生的现场也在同批工具全部配对后交付；系统中的唯一人物正文同步刷新。未执行的故障断点先沿用原有回执恢复逻辑，不在工具配对中插入新消息。

已经结束的行动来由不再反复作为新指令续接，其中独有的触发原话或引用保留。新的行动先检查窗口已有消息；跟聊沿用旧 SourceID 时，也依据实际交付游标避免把成员已整理掉的旧原话重新塞回。新的研究与到期预约仍可获得自己的原始任务来源。

同一条成功发送的正文通常存在于调用参数、回执和群聊回流三处。现在核对成功状态、消息 ID 及正文：参数保留原文，回执保留消息 ID、目的地、状态和扩展信息，自动回流不重复交付。完整原始工具结果与聊天原文仍可读取。不同消息 ID、不同成员的相同意见、失败调用、主动回读和不透明原生项目不按文本相似度删除。

旧窗口若完整保留倒序头部原话块与一一对应的行动来由，在加载时可恢复其交错位置；缺少对应关系或已经压缩的历史保持原样。修复不清空窗口，不批量改写原始聊天或人物。该结构修复没有被证明能单独解决评价趋同。
