# 成员自己的连续上下文

## 2026-11-07 的改动

以前每轮默认只取最近 16 条，再按每条 1800 字符、合计 10000 字符裁剪；结束一次行动后删除唯一执行窗口。短消息也会因为条数而消失，但已读位置仍推进到最新消息。工具循环又会把倒数第五条及更早的结果截短。普通新消息既能取消真人触发的生成，也能让发送工具退回 `not_sent`。这些规则把容量管理、已读交付和语义取舍混在一起。

现在三件事各自负责：

- **可靠交付**：按本人的连续交付位置读取新原话，不按固定条数或字符数裁剪；生成期间尚未交付的消息仍是未读。普通消息不取消已形成的回复，也没有人为随机等待。
- **工作窗口**：`working_contexts` 按成员和场景保存实际执行链；行动完成时，与回执和断点删除在同一事务落盘。安静结束也延续上下文。人物设定、控制和实际工作状态在下一轮使用最新现场，不由旧摘要覆盖。
- **语义整理**：成员在正常行动中自行选择 `organize_context`，不用额外的每消息分类调用。工具接受自由便笺、要保留的消息 ID、工具记录 ID，不设便笺长度或引用数量上限。校验归属后取回完整原文，等同批工具全部配对完成再替换工作窗口。

整理工具不结束工作、不修改特质、不删除原始记录。工具正文不再按调用新旧自动截短；默认资料索引保留来源入口，长正文由成员主动读取。已移出窗口的内容仍可通过 `read_history`、`read_tool_result`、`read_artifact` 找回。整理便笺属于本人，不作为共享事实或其他成员的记忆依据。

## 时机与提示词

没有“每次读新消息前先整理”的阶段。成员先读现场，再决定直接回应、继续行动、保持安静或整理；可以先回应再整理。模型提示包括：

> 工作上下文会延续到下次行动。话题转变、问题告一段落、资料已经读懂，或旧内容妨碍当前思考时，可以调用 organize_context 整理；无需每轮整理，也不必因为一句插话就放下原话题。可以先回应，再整理。

便笺保留不同人的看法、发生的更正、未完打算及必要原文；不把分歧合并成共识，也不把一次表达变成人格。原来的 `context_start_id` 提示被这一能力替代，已有历史起点仍可用于首次恢复。

容量兜底仍在模型请求边界：字节上界只用于放行明显能放下的输入；上界超出时先调用真实 token 计数，确实超过配置的输入预算才使用原生 `/responses/compact`。不在真实计数之前裁剪工具正文。原生压缩返回的整个窗口原样续接并保存，不拆改不透明 compaction 项目。

压缩指令中“已完成的搜索/保存不要再次执行”已移除。资料是否值得重新查由成员判断；精确参数缓存、5 分钟有效期、主动 refresh 和同一 tool_call 的幂等恢复仍由工具引擎负责。

## GPT-6 Mid-turn steering

当前接口用实际 `gpt-6.1-terra` 和 `gpt-6.1-sol` 验证通过。成员聊天/研究使用 Responses WebSocket；控制理解和无聊天目的地的个人活动沿用普通 Responses 请求。`DROPBY_MID_TURN_STEERING` 默认 true，可显式关闭。关闭后新消息仍在普通边界增量交付，不恢复旧取消逻辑。

- 仅真人追加消息发送 `response.steer`，BOT 发言不会被升级成用户指示。
- `response.steer.accepted` 只表示入队；实际自动续接结束后才确认交付，且不跨过尚未读到的其他成员消息推进游标。
- 每个自动响应单独结算。触发续接前按增长后的输入和输出预留预算；预算不足时保留消息用于普通接续，不吞掉输入。
- 如果原响应需要客户端工具，先执行返回的工具调用。本实现结束这次连接，在下一次包含工具结果的完整请求里接入仍未应用的新消息；没有把排队的 steering 当成已经应用，也没有重放工具。它不跨客户端工具调用维持 WebSocket 会话。
- 握手失败可以沿用网络重试，因为尚未发送 `response.create`。生成后的断线不自动重放整个请求；输入仍在消息库，未确认的费用保留未知。
- 明确停止、暂停、人物/成员权限编辑继续通过原有控制修订和取消执行生效。

协议来源：[OpenAI Mid-turn steering](https://developers.openai.com/api/docs/guides/steering)、[原生 Compaction](https://developers.openai.com/api/docs/guides/compaction)。

## 验证范围

本地测试直接检查实际下一次模型输入、持久窗口、原文回读和 WebSocket 帧：

- 30 条短消息全部交付；生成中到达的第 31 条不误标已读；新 Engine 从存储继续，安静结束不清空理解。
- 容量未满时主动整理旧工具正文，分歧和选定原话保留，同批发言只执行一次，原始长正文尾部可回读。
- 越权消息/同伴私有工具不能被整理引用；长便笺不被截断；普通发言不再因同伴消息返回 `not_sent`。
- 实际 token 可容纳时完整发送工具正文；原生压缩返回窗口及调用配对继续保留。
- WebSocket 正常续接、steered 中断、等待工具、steering 拒绝、断线、只注入真人，以及逐响应结算。

真实接口小样：Sol 两个响应输入 88 / 输出 11 tokens，按当前费率估算 $0.000286；Terra 两个响应输入 88 / 输出 50 tokens，估算 $0.000338。Terra 首次握手 EOF 未进入生成，随后应用实现验证通过。用的是隔离测试数据，没有向正式群聊发送消息，也没有把这一小样当作长期角色表现评测。

本轮未重启正式服务。新表由服务下次启动自动创建，原消息、人物与工具记录不改写。
