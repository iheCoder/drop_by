# 执行机制简化与辩论验收

2026-11-07。此文描述当前实现，旧验收文档里的次数配额不再适用。

## 删除的限制

删除每窗口/每根任务五条消息、六次后续或委托、参与判断四轮回忆、行动八轮工具往返及强制收尾、单个响应的工具数量配额、正常工作累计次数暂停、整项工作八分钟取消。删除每周调用次数和自主七美元子额度。旧环境变量不再生效；费用总预算、单请求超时、上下文/输出容量、并发和用户停止仍有效。

全员不行动且没有新消息时自然退出，不立刻空转重问；现有定时检查仍可再唤起。其他房间有真人请求排队时，在已保存工具结果或已发布消息的边界让出执行位。

## 必要的故障保护

- 只在外部模型/搜索请求处，对连接中断及可恢复 HTTP 错误退避重试，最多两次额外尝试；遵守 Retry-After 和取消。参数错误不原样重试。不层层重试整个任务。
- 同参数工具连续失败三次后停止该错误循环，参数 JSON 键序/空白不构成变化。成功读取、分页、改变参数不计入此限制。
- 用原始 tool_call ID 识别故障重放；不对角色消息做相似度去重。已成功的调用返回原结果；结果不明的写操作不直接重做，结果不明的只读操作可以重读。
- SQLite 只增加一份当前行动现场：工作、成员、会话修订、读到的位置及模型/工具消息。模型返回先保存，再执行工具；成功公开发布和清除现场在同一事务。恢复时考虑最新聊天和资料。
- 工作恢复入口恢复原工作，不发送新的用户催促消息。已完成、已取消、已被替代的工作不可通过此入口重放。
- 费用/尝试次数/内部错误不进入默认 trigger、work 或 read_work 视图。普通回复不解释运行故障；用户明确询问时才解释已知情况。
- 真正的输入超限与计数/压缩服务失败分别归类。已发消息保留，后续失败不伪装为全部完成。
- 新版的未知/在途预留单独显示。没有成功用量的旧请求不被假定免费，也不冒充精确服务商账单；旧账缺乏明细，未追溯重算。

保留模型自主判断，不新增人格分数、进展评分、固定发言顺序或中央发言裁判。

execution_recovery_test.go 覆盖：十二条成员消息自然结束；问题卡发送后故障续接不重发；同 tool_call 复用；写操作结果未知不重放；角色上下文不带预算/错误；503 请求恢复与400不重试；原工作恢复接口；预留与用量分开；重复失败与参数改变；发布事务中途故障后不出现半次提交。

## 验证边界

有限请求恢复不是对永久断网的保证。结果不明的写操作会停止并保留记录，尚不支持对任意外部写入自动核账。用户修改场景后恢复会采用当前资料，不能保证每次模型判断都符合主观预期。一次辩论不能证明长期人格或互动趣味已经稳定。

历史错误或预算解释如果已经被角色发在聊天里，本次不篡改这些历史消息。运行信息从默认上下文中分离，但模型在用户明确追问原因时仍可能参考真实历史。
