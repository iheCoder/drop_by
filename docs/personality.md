# 稳定的人物与实际经历

`Member.Profile` 保存一篇第一人称人格正文。底色、行为倾向和表达互动可以各有轻重，鲜明的特质要影响成员实际注意、选择和行动的方式。`Member.DomainProfiles` 按用户给出的领域记录具体品味、判断标准和做法，两者都能在朋友资料里编辑。`Direction` 和旧问答保留创建与设置记录。

人格原则上保持稳定。聊天、探索、任务结果和其他人的偏好可以成为具体经历与当下判断的材料，但不再自动改写人物。是否体谅别人、跟随同伴或坚持己见由各自特质决定，公共提示不为所有成员补同一种态度，也不要求评分必须不同。

## 输入、处理与输出

| 入口 | 输入 | 处理 | 输出与生效 |
| --- | --- | --- | --- |
| 创建 | 名字、可选方向或创建问答 | 一次模型生成完整人格，同时提取真人明确给出的具体领域偏好 | 保存人格和可为空的领域画像，首次私聊直接展示人格正文 |
| 手工编辑 | 编辑后的正文或领域列表及打开时的版本 | 直接保存 | 当前设定和可回看的版本 |
| 明确对话设置 | 真人原话、当前人物及实际问答语境 | 原行动模型用 `apply_instruction` 修改正文或指定领域 | 完整设定、变更说明及真人来源 |
| 可选情景问答 | 当前设定、完整问题和本次回答 | 按回答的范围和力度落实 | 更新本次涉及的人格或领域画像 |
| 普通交流与探索 | 当前人物、原话、工具结果、按需读取的记录 | 正常行动与记忆 | 实际行为、经历、近期打算 |

设置提示在 [`personality.go`](../internal/dropby/personality.go)，日常身份入口是 [`memberSystem`](../internal/dropby/engine.go)。举例含义不清时保留原有抽象程度，例如不把“像 Grok bot 这样有趣”直接变成特定产品兴趣。“这次说短点”按当前任务理解；明确要求调整角色本身时仍可修改特质。

## 单一身份与持久化

系统输入直接使用“你是 {name}。{profile}”，后接当前任务及运行说明。私聊、群聊和个人活动的 `self.domain_names` 提供领域名称，成员用 `read_domain_profile` 读自己所选领域的完整正文及版本。当前版本相同的已读结果可以沿用。背景记忆与关系笔记按需检索。

明确修改与其他工具同批执行时，先完成全部工具配对，再交付更新后的现场；唯一系统身份随之刷新。同批 `organize_context`、故障恢复和原生容量压缩都沿用当前人物。版本检查继续防止旧设置覆盖用户后来的编辑。

`profile_versions` 的一个版本记录当时的完整人格与领域画像。旧库中的人物和历史版本从空领域列表起步。启动时把旧 `reflect` 未完工作标为 `stopped`，已发生的工作、用量、版本、原消息、工具结果都可回看。

升级不自动恢复旧版本或重新生成已有成员。此前自动更新已经写入的人物仍可在历史里查看、放回编辑器后由用户保存；旧来源显示为“旧版自动更新”。从当前可见人物开始保持稳定。

## 验证

`personality_test.go` 检查旧库升级、未完后台停止、原始来源与历史版本保留、明确修改立即生效、同批整理、旧草稿恢复和重启换群。`context_order_test.go` 检查连续三轮的真实交错顺序、重复消息来源、原生协议不变与旧窗口可确定的修复。原生压缩测试检查实际请求中当前人物仅有一份。

`TestLivePersonalityContinuity` 与 `TestLivePersonalityScenarioAnswer` 默认跳过。显式设置 `DROPBY_LIVE_PERSONALITY=1` / `DROPBY_LIVE_PERSONALITY_QUESTION=1` 及独立 `DROPBY_PERSONALITY_DATA_DIR` 后，使用真实创建接口、问答、成员行动和工具验证名字创建、职业外聊天、临时要求、审美不同、明确编辑、含糊例子、实际探索与后续交流；完整消息、人物版本、工具结果与费用保存在独立目录。

`domain_profiles_test.go` 检查一次创建、领域全文交付、同批修改后的回读和版本冲突。用 `DROPBY_LIVE_PERSONALITY_CREATIVE=1` 运行 `TestLivePersonalityCreativeWriting`，在独立库内用同一道创作题对照完整设定、仅人格和空白设定。指定独立 `DROPBY_PERSONALITY_DATA_DIR` 可以保留作品原文和工具记录。

本次简化来自[提示删减与连续场景实验](../project-cognition/investigations/active/investigation-personality-subtraction-validation.md)。实验支持更小的运行协议与稳定人格，但首次评价仍会受他人纯态度影响；不能把结构测试通过或评分不同当成长期人格辨识度已经解决。实现后的验收与部署记录见[本次落地记录](../project-cognition/investigations/active/investigation-personality-implementation.md)。

## 旧版自我整理的历史验收（已停止采用）

使用当前配置的 Sol 与 Terra，在独立账本运行连续场景、无旧聊天的前后版本对照和真实情景卡片回答。共 38 次计费请求，包含网页工具，账本估算 $0.217844，无未结算预留；没有修改正式成员。

| 场景 | 观察到的行为 |
| --- | --- |
| 名字创建 | 小禾生成了温和但有主见、植物与料理等倾向；阿澈从设计师方向生成独立尝试、干幽默等特点，没有编造具体人生经历 |
| 职业外话题 | 猫碰倒杯子时回应“猫负责制造事故，杯子负责承担责任”；没有转向桌面设计 |
| 临时要求与不同审美 | “这次说短点”只得到简短建议；用户不喜欢极简时，阿澈保留自己的简洁审美，人物说明均未直接改写 |
| 明确修改 | 外向、主动开话题写入同一成员资料，其余审美与互动特点保留 |
| 含糊例子 | Grok bot 没有进入长期说明，也没有据此补出 AI 产品兴趣 |
| 实际经历 | 成功读取 Excalidraw 与 tldraw 网页、进行两次检索，保存一个故事画布 HTML 原型；没有宣称已接入 SDK 或完成多人验证 |
| 自我整理 | 增加“让人愿意动手、接着玩”的关注，以及适度提示与接续入口的判断；保留简洁审美、外向和干幽默 |
| 后续行为 | 新故事玩具优先考虑留悬念、接力和可选提示；转回游戏与猫的话题后，没有继续推销画布或协作 |
| 真实情景卡片 | 用户选择“先自行试一小轮，再带结果交流”，实际聊天调用写回这项倾向，没有把例子“整理笔记”当作长期兴趣 |
| 浏览器 | 隔离夹具中的名字创建、介绍展示、编辑保存、变化历史、恢复后保存和刷新通过；375px 页面无横向溢出，控制台无错误 |

原始记录保存在 `data/personality-acceptance/personality_eval_8fad1c89e1a28fbc53eef577.json`、`personality_transfer_b4e3682ddde21582e61f27f1.json` 和 `personality_question_e49bdb8dd7bfde4349b1ea17.json`。截图在 `output/playwright/personality-history-mobile.png` 与 `personality-restore-mobile.png`。这些是本地验收产物，不进入版本库。

验证边界：连续聊天能观察到更新后的合理行为，但旧经历也可能影响选择。新会话对照将更新前后说明分别放入没有旧消息、记忆和作品的新身份：两者分别建议“楼下见面会”和“邻居交换台”，差异尚不足以证明稳定的长期人格辨识度。这是一次有限场景验收，尚未进行多人连续相处盲测，也不把生成的原型当作已经完成真实多人使用验证。浏览器使用隔离模型夹具，模型语义由上述独立真实调用验证。
