# 人格与后台自我整理

人物说明是 `Member.Profile`，直接展示、编辑并用于交流与行动。自我介绍、特质与底色共享这一份自然语言，不新增隐藏人格、固定特质栏目或人格数值。`Direction` 和旧问答仅保留创建与设置记录，不重新注入当前人物。后台与前台都不套用统一的审慎、简短、活跃或分享风格。

## 输入、处理与输出

| 入口 | 输入 | 处理 | 输出与生效 |
| --- | --- | --- | --- |
| 创建 | 名字、可选方向或创建问答 | 一次模型生成具体起点；不编造实际人生经历 | 保存完整人物说明，首次私聊直接展示 |
| 手工编辑 | 编辑后的说明及打开时的版本 | 直接保存，无模型 | 当前说明和可回看的版本 |
| 明确对话设置 | 真人原话、当前人物及实际问答语境 | 原行动模型使用 `apply_instruction` 落实相关修改 | 完整说明、变更说明及真人来源 |
| 可选情景问答 | 当前人物、完整问题和本次回答 | 提炼回答已表达的含义，保留其余特点；意义不明的例子保持原有抽象程度 | 完整说明或不变；工具配置不参与修改 |
| 后台自我整理 | 当前人物、新交付的原话及工具结果引用，按需回查的实际记录 | 独立上下文中的一次语义整理，可回读来源；不做第二轮审核 | `profile`（完整说明或 null）、`change_note`、`source_ids` |

具体提示词在 [`personality.go`](../internal/dropby/personality.go)。角色设置问答的生成提示在 `CreateQuestions`，前台明确修改的工具契约在 `instructionDefinition`。抽象的“有趣”可以暂时保留，不能擅自把一个产品例子改成长期兴趣；已有具体特点也不因新回答含糊而全部退回空泛形容词。

自我整理可以增加兴趣、修正判断、调整互动和表达，也可以合并重复描述、删去已不贴切的特点。一次有分量的经历可以形成变化，不要求累计次数；没有新认识就不重写。某个特点暂未表现不会按时间自动删除。事件过程、计划和他人的偏好仍留在来源记录，不改写成“我是什么样的人”。

## 异步执行与持久化

前台不调用人格整理模型，也不接收成长任务。现有行动循环在模型成功接收消息、工具产生真实回执时登记来源 ID，重复 ID 只存一次。不同成员登记各自实际接触的材料。工具失败状态与作者信息原样保留。

现有定时器检查新来源，沿用 `DROPBY_EXPLORE_INTERVAL` 合并后台机会；无新来源不调用。存在可继续个人活动的聊天时创建个人 `reflect` 工作，普通任务优先。前台工作到来会取消尚在生成的低优先级请求，不等待其结束。模型调用期间不持有成员行动锁、不修改前台上下文；提交只用短事务，成员忙碌就保留结果稍后提交。

已完成的整理结果复用 `work.result` 保存，重试无需重复生成。提交时对照当前人物版本，若用户已编辑则重新基于当前资料理解；新到的经历保留给下一批。人物、来源游标和工作完成原子提交，没有变化也推进游标。后台更新不提升房间修订号、不取消正在进行的群任务。旧故障断点恢复时比较人物版本，对未执行的旧调用重新判断。

存储增加三项实际职责：`profile_versions` 支持变化回看和并发版本；`profile_experiences` 保存各成员实际交付过的来源引用；`profile_reflections` 保存已处理位置与调度时间。这些不是三套人格。旧成员不重新生成、不自动批量重做历史；从升级后新交付的经历开始整理，原说明首次修改时留档。

运行场景中的 `self.profile` 是当前值。系统提示不再重复拼接人格，协调者的成员列表不再重复自己的说明。主动整理后使用更新后的场景；原生容量压缩时当前人物精确保留，原话仍交由压缩处理。历史自我介绍和旧发言继续作为历史存在。

## 验证

机械场景见 `personality_test.go`：后台生成不阻塞前台、忙碌时延后提交并复用结果、用户编辑优先、来源去重、未交付消息不算经历、失败状态保留、无变化推进游标、修改与上下文整理同批发生、故障恢复不执行旧人物草稿、重启和换群连续性。原生压缩测试检查实际请求里保留且只保留一份当前人物。

`TestLivePersonalityEvolution` 是默认跳过的真实模型连续验收。它通过生产创建接口、成员行动、实际工具、独立后台整理和后续聊天运行，记录全程人物、原话、工具结果与累计费用。单独设置 `DROPBY_LIVE_PERSONALITY=1` 和 `DROPBY_PERSONALITY_DATA_DIR` 运行；使用独立数据，失败重试不清空账本。场景包括名字创建、猫和晚饭、临时要求、不同审美、明确修改、含糊的产品举例、实际探索和制作、后台变化、后续选择及成员差异。输出记录供人工阅读，不把“写了记忆”或“所有成员都说话”视为体验成功。

### 2026-11-08 实际结果

使用当前配置的 Sol 与 Terra，在独立账本运行连续场景、无旧聊天的前后版本对照和真实情景卡片回答。共 38 次计费请求，包含网页工具，账本估算 $0.217844，无未结算预留；没有修改正式成员。

| 场景 | 观察到的行为 |
| --- | --- |
| 名字创建 | 小禾生成了温和但有主见、植物与料理等倾向；阿澈从设计师方向生成独立尝试、干幽默等特点，没有编造具体人生经历 |
| 职业外话题 | 猫碰倒杯子时回应“猫负责制造事故，杯子负责承担责任”；没有转向桌面设计 |
| 临时要求与不同审美 | “这次说短点”只得到简短建议；用户不喜欢极简时，阿澈保留自己的简洁审美，人物说明均未直接改写 |
| 明确修改 | 外向、主动开话题写入同一成员资料，其余审美与互动特点保留 |
| 含糊例子 | Grok bot 没有进入长期说明，也没有据此补出 AI 产品兴趣 |
| 实际经历 | 成功读取 Excalidraw 与 tldraw 网页、进行两次检索，保存一个故事画布 HTML 原型；没有宣称已接入 SDK 或完成多人验证 |
| 自我整理 | 增加“让人愿意动手、接着玩”的关注，以及适度提示与接续入口的判断；保留简洁审美、外向和干幽默 |
| 后续行为 | 新故事玩具优先考虑留悬念、接力和可选提示；转回游戏与猫的话题后，没有继续推销画布或协作 |
| 真实情景卡片 | 用户选择“先自行试一小轮，再带结果交流”，实际聊天调用写回这项倾向，没有把例子“整理笔记”当作长期兴趣 |
| 浏览器 | 隔离夹具中的名字创建、介绍展示、编辑保存、变化历史、恢复后保存和刷新通过；375px 页面无横向溢出，控制台无错误 |

原始记录保存在 `data/personality-acceptance/personality_eval_8fad1c89e1a28fbc53eef577.json`、`personality_transfer_b4e3682ddde21582e61f27f1.json` 和 `personality_question_e49bdb8dd7bfde4349b1ea17.json`。截图在 `output/playwright/personality-history-mobile.png` 与 `personality-restore-mobile.png`。这些是本地验收产物，不进入版本库。

验证边界：连续聊天能观察到更新后的合理行为，但旧经历也可能影响选择。新会话对照将更新前后说明分别放入没有旧消息、记忆和作品的新身份：两者分别建议“楼下见面会”和“邻居交换台”，差异尚不足以证明稳定的长期人格辨识度。这是一次有限场景验收，尚未进行多人连续相处盲测，也不把生成的原型当作已经完成真实多人使用验证。浏览器使用隔离模型夹具，模型语义由上述独立真实调用验证。
