# 个人经历、召回与纠正

日期：2026-11-07。实现范围是成员自己的经历笔记怎样进入下一次选择，以及理解被纠正后怎样停止沿用旧结论。人物仍由自然语言描述，不增加人格分数、好感度、固定关系阶段或强制发言角色。

## 数据与执行路径

一条经历属于一个成员。正文简述实际发生或听说的事、自己的理解、适用场景及可能影响的行动；允许没有形成新认识，不要求每次合作都产生感悟。涉及的人与原始消息/成功行动另存标识，来源去重。保存前的真实性核对会看到原作者、来源原文摘录和先前版本，区分事实、转述、理解与计划。程序负责出处存在、访问范围、版本及执行边界；语义是否贴切仍依赖模型判断。

`remember` 新建笔记；更新或删除时必须带原 ID 与已读 `revision`。核对模型返回后，事务再次检查版本，避免另一会话的迟到草稿覆盖新纠正。旧版只供显式审计，普通检索和自动上下文只读取当前版本。历史笔记读写工具日志的正文也从默认输入中撤下，保留回查入口，防止旧结论通过工具快照重新进入下一次判断。原始聊天不会被删除或改写。

成员在决定发言之前就可以检索、写入、纠正笔记，最终仍可选择沉默。首句行动也开放记忆写入。明确的长期偏好不能只放进本群 `state`/`guidance`，否则换群就会丢失；当下挂念仍归当前状态，一次性的时间地点仍归当前任务。重要经历、合作理解按需保存，没有额外启动逐句总结或全员后台画像任务。

沿用既有范围：`conversation` 是当前聊天笔记；`member` 携带自己的非敏感经历与相处理解。同伴不能读另一个成员的内部笔记；跨群可携带的理解保留出处标识，但不会因此获得其他群或私聊原文的访问权限。原始六列 `memories` 保持兼容，新增附表保存元数据与修订。旧笔记按第 0 版读取，首次改写时存档；不虚构旧数据缺失的依据。

## 当前任务优先

默认召回从本人可访问的全部当前笔记中按相关性找候选，不再只看最新的几条。查询取当前指令、实际触发消息及最近三条现场消息；人物设定不拼成检索词，避免一个兴趣让所有话题都反复回忆旧事。

当前实现使用本地 BM25，中文相邻字对与英文词提供线索；裸数字不独立触发召回，避免 `21:10` 找回编号 21 的无关档案。它不是人格或信任评分，也不是向量语义搜索。没有匹配时允许空窗口，不以无关新笔记填满。换一种表达仍可能漏召回，成员可以用 `search_memory` 换词/翻页，再 `read_memory` 看全文和来源。

自动记忆窗口最多 6 条，每条正文摘录约 600 字符，**连元数据合计最多 3600 字符**。身份、当前状态、最新条件、触发消息和未完工作独立保留。更长原文按工具读取，仍受既有完整请求容量与续接机制限制。此界限约束输入体积，不决定谁信任谁或应不应该成长。

## 自动检查

新增六项离线场景覆盖：独立视角与同 ID 纠正、原作者与跨群来源边界、并发旧写入拒绝、大量无关笔记下保留当前任务、沉默时完成纠正且不重放旧日志、旧库升级与删除。检索案例含 350 条更新的无关长笔记，验证旧相关经历仍可进入固定窗口，时间数字不带回无关记录。

## 裴船、石粒的真实连续场景

使用本地已有两位成员的实际资料副本，真实调用既有 Responses 模型 `gpt-5.6-sol`，普通判断 `none`、后续行动 `high`。所有消息、记忆、作品和账本均在隔离目录 `data/personal-memory-acceptance/`，未写入正式聊天。验收把已安排的短任务提前执行，未模拟数天时间流逝。单次最多两条公开消息、六次工具往返，输出上限 2500/7000。

## 结论边界

已验证的是有来源的个人笔记 → 相关召回 → 同 ID 纠正 → 后续实际动作这条链路，以及有限上下文和版本保护。合作理解目前仍偏向做事习惯，具体的关系差异较薄；没有用一次实验宣称几个月的人格成长成立，也没有通过强制反对、强制感悟、给人打分或自动改写稳定资料来制造差异。

本轮没有做长期 A/B 对照、向量检索、自动人格训练或全量旧聊天再加工。短场景里的协作可同时受到初始特质、当前任务和已有“不重复制作”规则影响，无法把全部行为变化归因于记忆。后续相处中应继续审阅不同成员是否形成有依据的个人关注和关系理解，特别检查换词漏召回、过度泛化和反复提旧事。
