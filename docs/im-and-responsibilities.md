# IM、对话职责与上下文续接

本轮对应用户确认的完整体验改进方案。改动沿用现有工作队列、角色判断、SQLite 记录和 Responses 调用，没有引入给人物分配固定戏份的中央主持人。

## 已定位的问题

石粒的一项研究已成功保存 9,210 字符的 Markdown，随后在本地容量检查失败。此前估算使用 UTF-8 字节上界再加既往输出 token，偏保守；仅折叠工具返回正文，不能消除 assistant 函数调用中的完整作品参数。故障并非证实模型窗口已满，也不能把已保存草稿等同于已完成公开交付。

原接话提示还明确要求引用所接消息，与 `reply_to` 可选的协议冲突。群聊审查中的两个样本分别有 20/22 与 13/13 条 BOT 消息带引用。这个比例是旧问题的证据，不作为新实现的目标比例。

## 当前行为

- 全局「＋」发起私聊、建群或认识朋友。建群使用浮层搜索选人后直接创建，名称与头像可在群资料里修改（后续「浮光」界面更新，详见 `glass-ui.md`）。群资料支持添加、移除成员，移除保留历史与成果并停止该成员在本群的未完工作；修订和成员资格检查阻止旧回复/工具继续提交。
- 自己的头像进入个人中心，支持名字、默认图标、颜色和本地 PNG/JPEG 图片。图片在浏览器裁剪成缩略图，原照片与 EXIF 不上传。群头像不进入模型的文字上下文。
- 周额度只在个人中心呈现；聊天仅显示当前受限状态。恢复后撤下提示并重新检查工作。旧预算提示保留在数据库，聊天和列表查询不展示它们。
- Markdown 使用本地固定版本的 Marked 与 DOMPurify。允许文本、链接、标题、列表、代码、引用和表格；移除脚本、图片、表单、危险链接。HTML 作品继续在独立 sandbox 内预览，源码仅作为文本显示。
- 预览工具栏区分版本、下载、预览/源码与展开。单版本无下拉；切换预览/源码保留 iframe 的交互状态。关闭页面保留会话草稿并恢复入口焦点，表单关闭后解除 DOM，迟到保存不能重新打开编辑页。

## 职责与人物判断的边界

`responsibilities` 保存群里已经形成的组织约定：成员、自然语言范围、真人来源，以及可选的具体工作 ID。空范围是长期群约定；具体工作 ID 是临时事项。工作 `parent_id` 表达实际委托/续接关系，`root_id` 保留原费用和自主执行边界，两者不互相替代。

长期 A、临时 B 可以并存。当前事项沿最近父链找到组织者；交接重新路由尚未处理的结果回报并保留已有产出。撤销职责不会取消研究；明确取消整件事时停止其后续，晚到结果不会重开它。`delegate_work` 的 `coordinate=true` 可以授权同伴组织子事项；`close_responsibility` 允许角色在实际结果收齐后结束自己的临时职责，不修改长期约定。

具体执行任务与组织职责分开。例如「A 协调，再请 B 制作」只有 A 获得组织职责，B 的具体工作由 A 的工具真正安排。真实模型首轮验收曾混淆这两个概念，导致 A 说“已请 B”却没有委托记录；已据此收紧控制解释与完成性核对，后续重新验证实际委托链。

`@` 优先给予对应成员判断机会，其他人仍可自然补充。只有真人明确要求“其他人先别说”时才限制当前第一轮，之后或其他话题恢复。成员各自决定认同、补充、独立观点、玩笑或沉默；引用独立选择，不由选择过哪些背景消息自动填充，不设置引用率或相似度指标。

## 上下文续接

短请求仍用保守上界快速放行，可回读工具正文优先折叠。超过上界不直接判失败：调用 `/responses/input_tokens` 核对实际容量；确实超过本地工作窗口时在完整工具配对边界调用 `/responses/compact`。核心规则独立保留，完整原生输出整体续接，不能挑选、改写加密状态或截断函数参数。

压缩与生成均计入预算并按返回用量结算。计数/压缩服务失败保留工具、工作和成果，调度器可从存档重新构建窗口继续；重复失败会暂停供查看，不无限重试。原生压缩仍要求输入符合服务商窗口，不能宣称任何长度都会成功。身份、目标、状态及已保存成果 ID 保留；聊天、作品、工具原文不删除，可通过已有工具回读。

确定性测试覆盖实际计数纠正字节误报、原生输出与函数配对、工具循环继承新窗口、计数失败不扣生成预留、资料/成员 HTTP 路径、离群旧发布与工具拦截、额度结算恢复、旧提示隐藏、长期/临时交接、子事项授权、撤销与取消的差别，以及明确先发言的范围。

2026-11-07 的最终 `go test -race ./...` 通过 102 个顶层测试，计入子测试共 119 个；7 个需要显式开启的外部验收默认跳过。`go vet ./...`、两个前端入口的语法检查、`git diff --check` 和可执行文件构建均通过。

三个单独开启的真实 OpenAI 验收已通过：

- 实际输入计数、原生压缩、继续生成，保留已保存成果的 ID 与版本。
- 从真人话语形成临时职责，检索旧约，真实调用 `delegate_work`，同伴保存 HTML，负责人用 `read_work` 核对完成结果，整个队列结束。最终一轮为 19 次调用；不以一句“已安排”或回报队列的单一状态作为成功证据。
- 三个不同设定的成员回应同一闲聊：出现不同切入、玩笑和独立观点，三条回复均未使用引用，后续都选择不再接话。这是一个可检查样本，不规定每次都应三人发言或都不引用。

浏览器在隔离的真实服务与数据库上完成 34 项流程、内容和响应式检查，另测了额度限制到恢复的实际状态切换。覆盖资料与群头像上传、建群前后退保留填写内容、成员增删、Markdown 与危险内容清洗、HTML 交互与源码切换、选择旧版本并下载、侧栏展开、草稿与焦点保留、SSE 更新不冲掉未保存表单，以及迟到保存不重新打开已离开的页面。1440、797、390 像素宽度均检查了实际布局；额度恢复由 SSE 驱动撤下提示，没有手动刷新页面。隔离服务未配置模型密钥，因此这项额度浏览器检查仅投影模型就绪标志，额度与数据库状态来自真实服务。

真实验收（含定位问题的重跑）累计记录 94 次调用、约 $2.885 的本地估算用量；其中一次被测试取消的在途请求保留保守预留，不把它假称为已经得到服务商最终账单。该用量统一计入本周记录。合成角色、UI 测试聊天、委托与偏好均留在隔离数据库。测试记录与截图位于被 Git 忽略的 `test-results/im-live-20261107/` 和 `output/playwright/im-acceptance-20261107/`。
