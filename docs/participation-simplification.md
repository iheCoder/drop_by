# 参与机制减法与辩论验收（2026-11-07）

## 修改的原因与范围

原始现场是：真人请青雉组织裴船和石粒讨论 AI 对程序员的利弊，并排除爱情导师。青雉发出开场邀请后，成员已被再次唤起，但各自等待另一位辩手或主持人，没有继续。一次判断还把对爱情导师的排除误套到另一位成员。

代码中叠加了共同人物提示、参与判断、实际发言、记忆、协调和后续指令。“通常一到三句话”“不催回复”“不要为了说话而说话”等要求，超出了工具/运行协议，替所有成员规定了共同社交习惯。本次删除这些统一要求，不给辩论编写特例或固定发言顺序。

- 人物身份与原有 profile 明确放入本人决策和行动的指令。没有改写正式成员资料。
- 共享层保留事实来源、实际工具效果、权限、用户明确停止和更正等必要约束。
- 参与与表达由人物特质、当前状态、目标、经历和最新对话决定。发言不必有新信息，沉默也不被当作默认正确答案。
- 记忆来源、相关召回、原 ID/revision 纠正和跨场景边界继续保留；合并重复的记忆操作说明。
- `memberPrinciples` 从 736 个字符降至 230，`memoryContextPrompt` 从 1308 降至 484，`coordinationPrompt` 从 797 降至 370；这三段共减少约 62%。这不是整个请求的 token 降幅，工具定义、真实上下文、人物资料仍会占用空间。
- 模型分工保持 Luna / Terra / Sol，没有通过切换模型或篡改原有性格让测试通过。

## 观察与续接

已有 `schedule_followup` 就能预约稍后检查某件事。到期重新读取当前消息和工作，用原有 `read_history` / `read_work` 补查，成员决定接下来是否发言、催促、调整安排或结束。只补清工具用途，没有新增事件监控服务、人格评分或等待状态机。

真实验收又发现：单次 `MaxTurns=5` 窗口结束时，最后一条消息可能还没有被其他成员回应，就停止处理。因此仅在发布达到窗口上限时，排入一次面向全群的 `followup`，来源为真实末条消息。

续接共享原 root 的自主发言配额和预算，不获得全新额度；全员 pass 不创建续接，新真人消息会替换旧续接，重复结束同一窗口不重复排队。单次窗口上限与整条自主链上限仍然存在，不保证讨论无限进行。它不指定主持人、不强制发言，也不根据“没人说话”不断重试。

## 真实模型验收

代码：`internal/dropby/debate_live_test.go`。显式环境变量开启收费调用，使用独立 `data/debate-acceptance/`，未向正式群发试验消息。报告包含原话、个人判断、实际工具、工作状态和累计用量。

| 场景 | 实际结果 |
| --- | --- |
| 原始成员资料＋原始请求 | 青雉开场；裴船主动选利大于弊；石粒选反方并陈述；青雉继续组织。也由此发现了 5 条窗口的中断问题。 |
| 原始成员资料＋原封不动的青雉开场 | 两位辩手选边、陈述和互相反问，石粒承认原本也偏向正方，选择辩护反方；没有写死观点或先后。青雉实际预约复看，后来收束并结束临时职责。 |
| 慢热参与者的隔离变体 | 仅在试验副本里把两位参与者改为慢热，主持人主动安排先后。双方选择相近立场后，围绕新人岗位、收益分配和证据标准交锋，最后青雉收束。没有强迫一人赞成、一人反对。 |

最终原始开场案例有 8 条成员消息（其中一条是重建的原始开场）；慢热变体有 9 条成员消息。两种场景中爱情导师均未参与。断言检查指定辩手确实参与、排除成员没有发言、没有把口头辩论变成后台研究；具体交锋质量和推进方式另以实际文本人工检查，不用“必须由谁推动”作为通过条件。

验证边界和中间失败全部保留：

- 第一次重建开场的测试用旧会话修订号调用控制，触发 `ErrStale`；修正测试夹具，未修改正式修订保护。
- 隔离验收初始费用上限过小，多次因并发调用的预留不足中断。账本未重置，后来缩小口头辩论的输出预留，并将试验累计上限定为 $1.50；正式 $20 周额度不变。续接原工作，保留已生成内容，没有不断重开直到挑到好结果。
- 一次到期复看出现 HTTP 400；后续带失败请求诊断的复跑未再出现，未确认原始原因，也不声称修复了所有外部 API 错误。
- 最后两次续接均通过：原始开场案例与慢热变体都完成了工作处理。全部尝试共 174 次模型调用，应用估算 $0.788603，包含失败尝试。不是服务商账单。
- 实验推进了成员已真实预约的时刻以避免长时间等待；未凭空添加“请继续辩论”消息。尚不能据此证明长期人格差异或每次运行都会采用不同推进方式。

## 小交互修复

- 工作提醒在主动打开朋友动态后标为本机已读，刷新不再次显示；原始失败记录仍保留。重试次数、状态或结果变化后重新提醒，SSE 自动刷新不把新故障自动当作已读。
- 浮动详情面支持外部点击关闭。面内点击/拖选不会误关；不抢用户准备点击的控件焦点。裁剪窗口支持点击外部，只关闭裁剪这一层。
- 个人、朋友、群头像改用 label 激活原生 file input，替代委托点击隐藏控件；键盘仍可直接打开文件选择器，并显示一致的焦点轮廓。没有复现原来所有环境下的上传无响应，不能据此断言其唯一根因。

在无 API 凭据的隔离 8094 实例中，用 Playwright 验证：读提醒后隐藏、刷新保持、新失败再次出现、外部与内部点击、Escape、头像浮卡、裁剪与编辑层级；个人/朋友/群的文字和图片入口均打开文件选择器，键盘入口也成功；实际 PNG 裁剪预览、保存及重开读取通过。390 像素宽度下浮窗没有越界，外部点击关闭有效。所有头像修改均只发生在复制数据库。
