# 工具接入规则与本次问题记录

## 2026-11-07：工具封装擅自缩减 Agent 能力

搜索只开放 query，内部写死 count=5、need_content=false；网页正文保存前被截到 16000 字符；搜索发布日期和站点等字段在解码时丢失。其他工具也存在固定页长、最近五个版本、查询只取八个词、任务时间自动压缩到固定区间等问题。结果是 Agent 无法调整探索范围，也无法回读已经被丢弃的资料。缓存并不是这些问题的根源。

这属于工具契约错误，不能靠修改成员特质、强制多搜几次或增加提示词补救。

## 新增或修改工具必须遵守

- 先核对当前供应商支持的全部参数。工具声明、参数解析、实际请求必须一致。默认值只用于省略参数；显式输入不得被悄悄覆盖、截短或忽略。供应商自身范围限制应清楚标注来源，不叠加任意数量或长度上限。
- 原生参数与本地执行选项分开。搜索站点、日期等使用供应商实际支持的语法，不创造无效 API 字段。缓存键包含实际请求参数；强制刷新不得复用旧结果。
- 完整保存供应商返回的数据和元信息，包括未知扩展字段。获取时间不是发布时间。默认上下文可以展示概览，但必须能够发现记录、按需读取完整正文和历史版本；当前主动读取的内容不能立即再次被固定摘要截断。
- 普通参数错误和工具失败是 Agent 的观察结果，返回可理解的原因供其修正。不要因为同参数失败固定次数就强制结束整个行动。取消、用户暂停、预算、数据归属及同次写入恢复仍按其真实语义执行。
- 区分有效空结果与异常响应；异常结果不得缓存。费用按实际外部请求处理，缓存命中不计费，确认免费释放预留，无法确认的保留未知，不能把未知当成实际收费或擅自释放。
- 不以节省费用为由限制角色的观点、搜索方向或发言方式。工具能力调整不修改成员特质。

## 最小验收

用本地模拟供应商核对实际请求：默认参数、自选参数、参数变化、缓存命中、强制刷新；核对长正文尾部和元信息可回读；核对错误可修正、空结果免费、失败重试不会积累已知免费的预留。读写工具验证超过旧限制仍可用，并保留归属、版本和暂停控制。测试不需要为了验收大量调用付费模型。

官方契约：https://api-docs.deepseek.com/zh-cn/api/search/ 、https://api-docs.deepseek.com/zh-cn/api/fetch/ 、https://api-docs.deepseek.com/zh-cn/guides/search/

## 2026-11-07：上下文层同样不能悄悄裁掉能力

工具完整保存之后，若行动循环仍按“只保留最近四个结果”或固定字符数裁剪，成员刚主动读取的内容仍可能丢失。上下文层应遵守相同契约：原文完整可回读，语义整理交给成员，容量不足先验证真实 token 数。已读游标只能代表实际交付，不能用最近一条消息的位置掩盖中间漏读。具体实现和验收见 [上下文管理](context-management.md)。

## 2026-11-08：不要把场景归属误作成员的表达禁令

此前把当前聊天 ID 同时用于检索范围与访问权限，导致本人私聊原文、记忆和作品到了群聊就不能引用；个人活动能读群聊，却不能整理其中原话。另有当前房间人物名单限制记忆主体、拒绝引用失败或旧笔记、固定截短关注与工作正文等规则。这些是未经用户要求的产品限制。

成员可回忆、整理、引用和分享自己知道的内容，是否分享由其特质、关系、语境与用户明确要求决定。来源房间、作者、工具类型及成功/失败状态必须如实保留，但不由代码裁定它能支持何种理解。当前场景用于默认选取，不构成跨场景禁令。

本轮移除本人记忆的跨房间读取/召回限制、开放各场景主动选择聊天读取、允许跨场景整理原话及回读工具、允许作者跨聊天分享作品卡，并移除个人活动最近八条/工作三十二条和相关正文的固定裁剪、记忆召回六条及字符总额。分页默认值仍可由调用参数改变。

保留的约束及具体理由：身份不能冒用（不能改他人记忆或取消他人工作）；未参与聊天不能凭 ID 偷读（参与关系才是来源访问依据）；用户明确暂停与预算设置必须有效；版本冲突及同次写入幂等避免覆盖更新和故障重发；消息回复/表情锚点仍属于目标聊天，保证 UI 引用的是实际消息。成员自己的记忆/整理日志不自动开放给其他成员，但本人可以主动分享其内容。

尚未在本轮处理的执行问题：系统现场重复追加、压缩成果落盘时机、steering 游标原子保存、同批整理回执冗余。这些不应与成员能力限制混为一项修改。

上述执行问题在本轮后续修复：最新现场替换重复快照，成功压缩及时保存，响应与交付游标一起保存，主动整理不再重复附带便笺及整批长正文。详见 [上下文管理](context-management.md)。


## 2026-11-08：整理不能吞掉尚未交付的新结果

曾把“organize_context 同批的只读工具结果”统一缩成回读入口，错误地将模型尚未看到的内容当作它已经决定舍弃的旧材料。整理只替换调用前已读窗口；同批新读取的实际返回内容和失败信息必须正常交付。不得禁止同批调用来规避问题，也不得要求成员反复读取才能看见结果。

自动召回与索引同样可能绕过成员取舍：取消固定上限不能变成默认灌入全部匹配记忆。默认输入不再自动加载记忆、关系笔记、历史资料和旧工作列表，成员按需检索；整理后不重新组装背景。行动来由一次性交付，已完成 outcome 留在运行记录，不作为下轮决定。

费用修复不能改写控制流：包装请求错误时保留取消/超时原始原因，确认未发出的预留释放与行动恢复分别判断。验收必须检查实际模型输入、恢复后的输入和账本，而不只检查工具 schema 或错误文案。


## 2026-11-08：确认同一消息后减少重复载体

人格简化后的上下文会核对 `send_message` 的调用正文和成功回执。消息 ID 与正文一致时，模型窗口保留一次发送原文，回执不再回显同一正文，群聊自动交付也不重复灌入；原始调用参数、完整工具结果及聊天消息仍全部落盘、可回读。失败、未确认和不同 ID 不视为同一来源；不修改原生调用参数、不拆改不透明协议项目，也不删去同伴的相似意见。

验收检查连续行动中的实际下一次输入、成功/失败的区别、协议配对、扩展字段与原始结果回读；主动 `read_tool_result` 的实际读取范围仍完整返回。
