# drop_by

一个由你和多个独立 AI 成员共同参与的持续聊天空间。成员可以群聊、私聊、互相接话，沿真实线索进行网页探索，把结果保存成可继续修改的文稿或 HTML 网页。关闭网页不会停止服务端已经允许的工作。

当前实现面向 **macOS / Linux、本机单用户**。后端使用 Go 标准库 HTTP 服务，SQLite 保存聊天、经历、工作、工具记录和成果版本，前端为随二进制嵌入的原生 HTML / CSS / JavaScript，不需要 Node 构建或额外数据库服务。

## 启动

需要 Go 1.27；模块指定工具链 1.27.3。首次运行会下载工具链与 SQLite 驱动依赖。

```sh
# 在已有 OPENAI_API_KEY 的终端中运行，不要把真实密钥放进仓库。
go run ./cmd/dropby
```

打开 <http://127.0.0.1:8090>。创建时只填名字、选择头像，立即进入私聊。第一条相识消息带一个可选问题：点选、自己输入回答或直接聊别的都可以，改聊其他内容会自然收起选项。点击聊天标题或成员头像可编辑名字、头像和人物说明，也能在聊天中说明长期偏好。头像支持 3 款照片预设、12 种图案、6 种图案颜色和 PNG/JPEG 上传；照片可拖动、缩放裁剪，确认预览后再保存。

「浮光」界面使用柔光背景、玻璃导航和青绿色气泡。左侧分为聊天与朋友两个视图，「＋」打开就近菜单；新建群聊可搜索朋友、查看或移除已选头像，选好后直接创建，群名自动生成。群详情里可以修改名称、上传群头像、添加或移除成员。左下角自己的头像进入个人中心，可修改自己的名字、默认头像或上传图片，并查看本周额度。输入 `@` 可以点选成员。消息采用左右气泡并渲染 Markdown 标题、列表、代码块、引用和表格，引用可跳回原消息；切换聊天保留各自未发送的草稿，阅读旧消息时新消息不会强制滚到底部。点击头像就近展开资料浮卡，可发消息、编辑或查看完整资料；创建、编辑和头像裁剪均在当前场景完成。完整资料、动态和成果按需浮动展开，不改变聊天宽度。窄窗口保留聊天，通过返回入口打开列表，未保存表单和选择在缩放时保留。

如果当前网络无法连接默认 Go 代理，可以仅为本次命令指定镜像：

```sh
GOPROXY=https://goproxy.cn go run ./cmd/dropby
```

希望关掉终端后仍运行，可以构建后在后台启动：

```sh
go build -o bin/dropby ./cmd/dropby
mkdir -p data
nohup ./bin/dropby >data/server.log 2>&1 &
```

服务必须保持运行，电脑也必须处于可运行状态；关机、休眠时无法执行网络探索。重新启动会恢复中断的工作。停止服务用正常的 `SIGTERM` 或终端 `Ctrl+C`，程序会取消生成并保留未完工作。同一数据目录只允许一个服务进程。

本机通过 macOS 系统代理访问 OpenAI，本机常用端口为 `7890` 或 `7790`。服务优先连接环境变量指定的代理；本机 HTTP 代理的 TCP 连接失败时，自动尝试另一个端口，不重发已经送出的请求。Go 不自动读取 macOS 系统代理；在这台机器手动重启时使用：

```sh
HTTPS_PROXY=http://127.0.0.1:7890 NO_PROXY=localhost,127.0.0.1,::1 go run ./cmd/dropby
```

代理地址以本机实际设置为准；当前后台实例已经带上该代理环境。

## 模型、工具和费用

默认由 `gpt-6-luna` 判断参与和找回记忆，`gpt-6.1-terra` 组织日常发言，`gpt-6.1-sol` 执行研究、控制理解和真实性核对。三个模型均通过 Responses API 调用，默认读取 `OPENAI_API_KEY`，地址为 `https://api.openai.com/v1`。搜索与网页读取仍独立使用 `DEEPSEEK_API_KEY`，其费用不属于 OpenAI 赠送额度。密钥只保留在进程环境，不写入 SQLite、不传给浏览器、不写日志。没有模型配置时仍可创建和编辑成员、查看聊天，相识问题不依赖模型；生成回应和理解自然语言偏好需要模型配置。没有搜索配置时不会宣称已经联网探索。

可用环境变量见 [.env.example](.env.example)。程序**不自动加载 `.env` 文件**，请由启动环境设置变量。当前生成接口只使用 Responses API。`DROPBY_BASE_URL` 与 `DROPBY_API_KEY` 指向正在使用的网关，三个模型职责分别配置；搜索服务独立配置。

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `DROPBY_ADDR` | `127.0.0.1:8090` | 只允许本机回环监听 |
| `DROPBY_DATA_DIR` | `data` | 数据目录；每个目录独立 |
| `DROPBY_MODEL` | `gpt-6.1-sol` | 研究、控制理解、真实性核对的主模型 |
| `DROPBY_DECISION_MODEL` | `gpt-6-luna` | 参与判断与相关经历检索 |
| `DROPBY_CHAT_MODEL` | `gpt-6.1-terra` | 普通发言，包括后续接话 |
| `DROPBY_WEEKLY_BUDGET_USD` | `20` | 每周估算费用总上限 |
| `DROPBY_CONTEXT_TOKEN_BUDGET` | `100000` | 完整输入的保守 token 上界与输出预留总容量，不是精确 tokenizer |
| `DROPBY_MAX_OUTPUT_TOKENS` | `8000` | 快速调用的输出与推理 token 总上限 |
| `DROPBY_EXPLORE_INTERVAL` | `30m` | 闲时探索的起始间隔；之后逐渐放缓，最多间隔 6 小时；具体后续按自己的到期时间运行 |

职责选择发生在已有调用节点，不额外调用模型分类。参与和发言使用 `none` 推理；主模型默认 `DROPBY_REASONING=low`，实际研究使用 `DROPBY_DEEP_REASONING=high` 和 `DROPBY_DEEP_MAX_OUTPUT_TOKENS=25000`。后续闲聊不会仅因不是首句而升级。身份、原话、记忆与工具结果继续属于同一个成员；核对不继承调用者的模型职责，使用主模型。原生压缩沿用当前请求的模型，不跨型号搬运加密推理或压缩项目。没有自动降级到旧型号或重放整段工具行动的回退。

所有模型请求使用 `/responses`、`max_output_tokens`、`reasoning.effort` 和 `text.format`，保留原生工具及加密推理项目。返回的 `commentary` 不会拼入业务 JSON；只读取 `final_answer`，同时保留完整原生项目供后续调用。不保留旧模型识别、Chat Completions 或旧参数分支。三个职责各自读取配置，设置主模型不会隐式覆盖参与与聊天模型。

费用按实际调用的模型及其官方 Standard 费率估算：Luna 输入/输出每百万 tokens 为 $0.10/$0.50，Terra 为 $1/$5，Sol 为 $2/$10；缓存读取和写入分别结算，不重复计入普通输入。原生压缩也使用当前模型的费率。费率来源与计算边界见 [模型费用估算](docs/model-pricing.md)。每周 20 美元按用户要求设置，应用不读取账户账单、余额或赠送额度到期日；不再额外限制调用次数。选型证据、接口修复和验证边界见 [模型选择记录](docs/model-selection.md)。

费用在调用前事务性预留，成功返回 token 用量后按该模型费率与缓存明细结算；未知结果保留保守预留。账本保留每日明细，按服务进程本地时区的**周一 00:00 到下周一 00:00**累计；本机显式设置 `TZ=Asia/Shanghai`。升级前本周费用一并计入，重启不会清空。金额用完与余额不足以预留下一次请求分别说明。新版额外显示尚未结算的在途/未知预留，旧账不凭空重算。额度只在个人中心显示；聊天仅在当前额度不足时提示，预留结算释放余额或新周恢复后自动撤下提示并重新检查待执行工作。历史额度系统消息保留在数据库，但不再出现在聊天或列表。重启后也会重新核对当前配置，实际预留仍不可绕过。旧 `DROPBY_DAILY_*` 变量需迁移到新的周变量，避免把旧 3 美元误认为每周 3 美元。实际服务商账单可能包含缓存折扣和价格变更，界面资源限制不等于精确账单。

联网工具目前采用 [DeepSeek Search & Fetch 官方接口](https://api-docs.deepseek.com/guides/search/)，搜索与读取按每次 0.00075 美元保守预留。深入推理与工具调用使用 OpenAI [Responses 推理接口](https://developers.openai.com/api/docs/guides/reasoning)，保留工具往返所需的加密推理项目，且设置 `store=false`；快速回应同样使用 Responses，没有其他生成接口或自动降级路径。请求都设置超时，失败不会伪造结果，也不会无限重试。

本轮参与机制删减了对所有成员统一施加的简短、不催促等社交要求。成员依据自己的特质、状态和目标决定参与；已有后续预约用于观察交流进展。成员自行决定继续或结束，不按消息数和工具轮数收尾。真实辩论与 UI 验收、失败记录和适用边界见 [参与机制减法与辩论验收](docs/participation-simplification.md)。

## 运行方式与边界

- 每名成员观察一段交流，根据人物说明、可见经历、当前关注和真实行动，选择零条、一条或多条消息作出 `speak / explore / revisit / pass` 判断。选择可跨越最新消息；各自意图保留到实际行动前，成员会重读此间的新发言，调整、缩短、转向或撤回。明确 `@` 优先提供机会，但不强迫回答；某位成员撤回不会结束其他人的机会，全员安静是正常结果。
- 成员看过的消息位置和是否说话分开记录。当前状态和目标以一小段带来源的自然语言保存，可随新消息变化或清除，不建立人格分数、心情数值或固定轮流职责。这份当前关注按聊天隔离，人物说明及既有可携带经历保有跨场景连续性。
- 相似措辞由发言成员结合上下文自行判断，不用中央相似度阈值删掉自然附和、共情或接梗。选择了不同人格不保证每句话都不同；实际多轮对话是否有趣需要观察，不能由消息数量或发言覆盖率证明。
- 在聊天中明确提出的持续性格、兴趣或相处偏好会合并到人物说明，临时任务和一次性语气要求不会自动变成永久设定。问题的回答归属于提问成员；选择题工具一次只保留一个打开的问题，用户改聊其他事不需要点“跳过”。
- 用户消息、修订号和待处理工作在同一事务落盘。新消息会取消该聊天正在生成的内容；即使外部请求未及时取消，旧修订也不能发布回复、保存成果或改写记忆。
- 公开聊天和研究是不同工作。“先别聊”立即停止公开讨论，研究可继续；“不用研究”立即停止该聊天的研究。带具体对象的自然语言由模型结合现有工作解释；模型不可用时，精确停止短语仍立即生效。恢复、局部停止、改方向也可用自然语言表达。
- 研究完成先保存结果，再生成独立的分享判断机会；是否提醒用户由消息的 `notify` 决定。浏览器通知只有在用户点击“开启通知”、页面仍打开且处于后台时可用。关闭所有页面期间不会发系统推送，消息完整保留供回来查看。
- 所有成员都具备本地文稿与 HTML 创作能力；新成员默认提供搜索和阅读，联网能力仍取决于实际服务配置。提问、经历、历史检索、安排后续和取消自己的待办等工具按当前情境提供。没有终端执行、第三方联系、消费、账户修改或公开发布工具。
- 人物说明、当前挂念、有效方向与未完成工作常驻；旧聊天、记忆、成果通过本地工具检索。参与判断之前就可查历史或整理经历；模型可选择新话题起点让无关旧原文退出默认窗口，记录不删除。长消息摘录保留头尾，完整原文可翻页。完整请求先折叠可回读工具正文，保守估算超限时使用 Responses 输入计数；确实需要时调用原生 `/responses/compact`，保留完整返回窗口，后续工具循环使用新窗口。恢复时保留已保存成果的回读线索，不要求用户缩短自己的问题。具体设计与验证见 [上下文与协调](docs/context-and-coordination.md) 和 [本次 IM 与职责改进](docs/im-and-responsibilities.md)。
- 组织职责从真人对话形成，例如「@小舟，以后需要一起做事时你帮忙张罗」或「这次让小岚组织」。长期群约定与具体事项的临时职责分别保留，群详情只展示实际约定与来源。负责人用 `delegate_work` 真正分工，可以授权别人组织子事项；接收者保留自身特质。结果、失败或暂停触发一次复看；交接保留成果并转移待处理回报，撤销职责不取消研究，取消事项则收束相关后续。完成后可以结束临时职责。
- 经历用带来源的自然语言笔记表达，不做人格分数或关系数值。当前群原始聊天只对该群可用；成员可以携带自己的非敏感经验笔记进入其他群和私聊。敏感内容识别依赖模型，**尚不提供经过验证的跨场景保密保证**，验收应使用非敏感数据。
- 成果实际保存于 SQLite，修改生成新版本。聊天中显示真实保存的成果卡片；HTML 支持预览、源码、版本选择和下载，Markdown 支持阅读和下载。继续聊成果会保留未发送草稿。预览在不透明来源的沙箱中运行页面脚本，不授予聊天 DOM、存储、弹窗或表单权限；CSP 限制外部资源和联网 API，但不能宣称完全网络隔离（浏览器仍允许框架导航自身）。下载的 HTML 是原始文件。
- 消息、私聊、经历和成果保存前，额外核对实际行动与来源，防止“AI 自称坐过椅子”等虚构身体经历传播为事实；只修正事实归属与证据强度，不替成员决定观点。核对本身也调用模型并消耗预算，不能当作已经证明的绝对防幻觉保证。
- 成员可以用 `schedule_followup` 为具体关注安排相对延时或带时区绝对时刻的一次重新考虑（不支持周期 cron），或用 `cancel_work` 撤销自己的未执行后续；到期先由本人读最新上下文，再决定是否行动，同伴可以接续真正发布的新话。闲时探索逐渐放缓，真人新交流会重置间隔，BOT 自己的消息不会不断重置。
- 自主后续保留来源，用于用量统计和资源排队；总预算对所有请求生效，不再另设后台子额度。普通分享默认不通知，行动、公开交流和系统通知仍分别决定。
- 请求短暂故障在该请求处有限重试；持续故障保留行动现场。动态中的恢复入口重启原工作，不伪造催促消息。成功工具结果可复用，发送与清除现场原子提交，避免故障重放。运行诊断留在详情，不默认进入角色上下文。见 [执行机制简化](docs/execution-simplification.md)。
- 同一成员跨场景共享身份和可携带经历，不代表采用不同底层模型或独立事实来源；多个成员意见一致不能当作独立证据。

| 文件 | 责任 |
| --- | --- |
| `cmd/dropby/main.go` | 服务启动、后台进程和退出 |

| `internal/dropby/coordination.go` | 群内职责、委托、真实结果驱动的协调接力 |
| `internal/dropby/request_context.go` | 整个模型请求的容量保护与可回读工具正文压缩 |
| `internal/dropby/preferences.go` | 对话偏好、资料与头像编辑、可选问题 |
| `internal/dropby/model.go` | 实际模型 HTTP 请求、成员创建、预算预留 |
| `internal/dropby/tools.go` | 真实搜索、阅读、成果版本、记忆和主动私聊 |
| `internal/dropby/http.go` | 本机 API、SSE、请求验证与浏览器访问边界 |
| `internal/dropby/web/` | 创建成员、群聊、私聊、完整聊天、成果查看 |

## 检查与验收

```sh
go test -race ./...
go vet ./...
node --check internal/dropby/web/app.js
go build ./cmd/dropby
```

自动测试覆盖过时结果拒绝、即时停止、局部更正、并发预算、重启恢复、无人回应、研究独立完成、实际工具失败、成果版本、跨群记忆可见范围、HTTP 边界、历史分页、明确 `@` 优先，以及无浏览器连接时继续执行。新增回归覆盖首位成员安排研究后第二位仍可参与、无真人消息的自主探索、未来研究不阻塞探索、长工具历史摘录及原文回读、Responses 加密内容不误触发上下文或预算限制、只填名字创建和跳过偏好。测试中的模型替身仅用于注入确定性边界，生产代码没有模拟回复模式。

初版真实服务验收记录在 [docs/verification.md](docs/verification.md)，前一轮产品对照在 [docs/experience-audit.md](docs/experience-audit.md)。最新的角色参与机制、聊天界面和真实模型／浏览器验收见 [docs/character-experience.md](docs/character-experience.md)。功能通过并不等于“朋友群已经有趣”；自然错落、长期关系、主动内容是否值得收到，仍需持续真实使用验证。

产品范围依据 [drop_by 产品需求说明 v0.1](docs/demand/drop_by%20产品需求说明%20v0.1.md)。

执行边界与故障续接见 [执行机制简化](docs/execution-simplification.md)。消息、工具往返和后续委托不再按次数配额截断；旧的相应环境变量不再生效。
