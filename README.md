# drop_by

一个由你和多个独立 AI 成员共同参与的持续聊天空间。成员可以群聊、私聊、互相接话，沿真实线索进行网页探索，把结果保存成可继续修改的文稿或 HTML 网页。关闭网页不会停止服务端已经允许的工作。

当前实现面向 **macOS / Linux、本机单用户**。后端使用 Go 标准库 HTTP 服务，SQLite 保存聊天、经历、工作、工具记录和成果版本，前端为随二进制嵌入的原生 HTML / CSS / JavaScript，不需要 Node 构建或额外数据库服务。

## 启动

需要 Go 1.27；模块指定工具链 1.27.3。首次运行会下载工具链与 SQLite 驱动依赖。

```sh
# 保留已有的本机配置。
cp -n config.example.yaml config.yaml
# 可在 config.yaml 填写 api_key，也可由启动环境提供 OPENAI_API_KEY。
go run ./cmd/dropby
```

打开 <http://127.0.0.1:8090>。创建时只需名字，可选填大致方向；系统生成并保存具体的自我介绍，首次私聊直接展示这份介绍。点击聊天标题或成员头像可编辑名字、头像和人物说明，也能自愿用情景问答调整特质、回看变化，并把历史版本放回编辑器继续修改。日常交流使用的就是资料页这份人物说明。头像支持 3 款照片预设、12 种图案、6 种图案颜色和 PNG/JPEG 上传；照片可拖动、缩放裁剪，确认预览后再保存。

「浮光」界面使用柔光背景、玻璃导航和青绿色气泡。左侧分为聊天与朋友两个视图，「＋」打开就近菜单；新建群聊可搜索朋友、查看或移除已选头像，选好后直接创建，群名自动生成。群详情里可以修改名称、上传群头像、添加或移除成员。左下角自己的头像进入个人中心，可修改自己的名字、默认头像或上传图片，并查看本周额度。输入 `@` 可以点选成员。消息采用左右气泡并渲染 Markdown 标题、列表、代码块、引用和表格，引用可跳回原消息；切换聊天保留各自未发送的草稿，阅读旧消息时新消息不会强制滚到底部。点击头像就近展开资料浮卡，可发消息、编辑或查看完整资料；创建、编辑和头像裁剪均在当前场景完成。完整资料、动态和成果按需浮动展开，不改变聊天宽度。窄窗口保留聊天，通过返回入口打开列表，未保存表单和选择在缩放时保留。

如果当前网络无法连接默认 Go 代理，可以仅为本次命令指定镜像：

```sh
GOPROXY=https://goproxy.cn go run ./cmd/dropby
```

希望关掉终端后仍运行，可以构建后在后台启动：

```sh
go build -o bin/dropby ./cmd/dropby
mkdir -p data
nohup ./bin/dropby >data/server.log 2>&1 &
```

服务必须保持运行，电脑也必须处于可运行状态；关机、休眠时无法执行网络探索。重新启动会恢复中断的工作。停止服务用正常的 `SIGTERM` 或终端 `Ctrl+C`，程序会取消生成并保留未完工作。同一数据目录只允许一个服务进程。

测光是另一个进程，不打开聊天数据库，也不进入成员上下文。主页读数据目录里的 `observe.sqlite`；测光用 `OBSERVE_DB` 指向这个文件，默认是 `data/observe.sqlite`。样例在 <http://127.0.0.1:8097/demo.html>。公开名称是 <https://www.dropby.ob.ai/>，和聊天的 <https://www.dropby.ai/> 分开。进程仍只监听本机回环，并接受这个域名的 Host。

```sh
go run ./cmd/observe
```

本机直接打开 <http://127.0.0.1:8097/>。监听地址用 `OBSERVE_ADDR`，默认 `127.0.0.1:8097`。

代理按请求协议优先使用显式配置的 `HTTP_PROXY` / `HTTPS_PROXY`（也支持小写），并尊重 `NO_PROXY`。没有配置时，macOS 按需读取当前系统的 HTTP、HTTPS 或 SOCKS 代理及例外列表；系统端口变化无需重启。其他系统未配置时直连。显式代理连接失败不会擅自换地址。

不运行后台代理监控，不探测固定端口。自动代理脚本（PAC/WPAD）暂不执行；仅启用自动代理时需显式配置代理地址。

## 模型、工具和费用

[config.example.yaml](config.example.yaml) 包含服务、搜索、预算和模型配置。启动默认读取工作目录的 `config.yaml`，也可通过 `DROPBY_CONFIG` 指定本机文件。仓库忽略本机配置，修改在重启后生效。

- `models.providers` 配置接入点的协议、API 根地址和 `api_key`。当前支持 `openai_responses` 和 `gemini_generate_content`。WebSocket 插话和显式缓存断点可按 Responses 接入点的能力启用。
- `models.scenes` 直接选择供应商、模型和原生参数。示例沿用 Terra 日常聊天、Sol 研究、Sol 个人探索、Sol 人物设定。研究和探索分别配置。请求中的上下文、工具、JSON 格式及续接状态由接入代码组装。
- 同一字段先读文件，其次才用环境变量和默认值。OpenAI 条目省略 `api_key` 时，依次查 `api_key_env` 指定的变量，或者默认的 `DROPBY_API_KEY`、`OPENAI_API_KEY`。自定义接入点只用自己的 `api_key` 或 `api_key_env`。搜索密钥可写在 `search.api_key`，省略时依次查 `DROPBY_SEARCH_KEY`、`DEEPSEEK_API_KEY`。
- 从旧配置迁移时，把接入地址填到 `models.providers`，把模型、推理和输出长度填到对应场景。之前的模型环境变量仍可给默认 OpenAI 接入点补充缺省值。其余变量见 [.env.example](.env.example)。执行显式开启的真实模型测试时，用绝对路径指定 `DROPBY_CONFIG`。

试用 Gemini 4 Hydrogen 时，可把示例里的 `Gemini` 接入点与可选 `chat` 段复制到本机配置并填写 Key。`base_url` 可以是 `https://generativelanguage.googleapis.com`，也可以是支持 Gemini 原生接口的中转地址。`generationConfig.thinkingConfig.thinkingLevel` 控制推理深度，`maxOutputTokens` 给推理与正文合计留出上限。生成会复用稳定的请求前缀，按返回的 `cachedContentTokenCount` 记录隐式缓存命中。默认在本地预估超限时调用 `countTokens` 复核。接入点不支持该接口时，可把该接入点的 `token_counting` 设为 `local`，改用本地估算判断容量。费用继续按生成接口返回的实际用量估算。

成员上下文的续接、主动整理、容量兜底与 GPT-6 Steering 见[上下文管理说明](docs/context-management.md)。

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `DROPBY_ADDR` | `127.0.0.1:8090` | 只允许本机回环监听 |
| `DROPBY_DATA_DIR` | `data` | 数据目录；每个目录独立 |
| `DROPBY_CONFIG` | `config.yaml` | 应用配置文件路径 |
| `DROPBY_WEEKLY_BUDGET_USD` | `20` | 每周估算费用总上限 |
| `DROPBY_EXPLORE_INTERVAL` | `30m` | 旧工作间隔与网络故障恢复间隔；自主唤醒按成员自己的节律 |

费用按实际调用的模型及其官方 Standard 费率估算。账本记录请求使用的接入点，直连和中转按同一个模型的官方费率估算。费率与缓存计算见 [模型费用估算](docs/model-pricing.md)。默认每周额度为 20 美元，在本机配置中管理。选型与验证记录见 [模型选择记录](docs/model-selection.md)。

费用在调用前事务性预留，成功返回 token 用量后按该模型费率与缓存明细结算；未知结果保留保守预留。账本保留每日明细，按服务进程本地时区的**周一 00:00 到下周一 00:00**累计；本机显式设置 `TZ=Asia/Shanghai`。升级前本周费用一并计入，重启不会清空。金额用完与余额不足以预留下一次请求分别说明。新版额外显示尚未结算的在途/未知预留，旧账不凭空重算。额度只在个人中心显示；聊天仅在当前额度不足时提示，预留结算释放余额或新周恢复后自动撤下提示并重新检查待执行工作。历史额度系统消息保留在数据库，但不再出现在聊天或列表。重启后也会重新核对当前配置，实际预留仍不可绕过。旧 `DROPBY_DAILY_*` 变量需迁移到新的周变量，避免把旧 3 美元误认为每周 3 美元。实际服务商账单可能包含缓存折扣和价格变更，界面资源限制不等于精确账单。

联网工具采用 DeepSeek Search & Fetch，搜索与读取按每次 0.00075 美元保守预留。模型请求使用场景选定的协议，工具往返用的加密推理项目或签名随本地行动记录保存。OpenAI Responses 请求设置 `store=false`。请求失败由现有逻辑重试或恢复，仍使用场景指定的接入点。 [DeepSeek Search & Fetch 接口](https://api-docs.deepseek.com/guides/search/) · [OpenAI Responses 推理接口](https://developers.openai.com/api/docs/guides/reasoning) · [Gemini GenerateContent 接口](https://aistudio.google.com/api-reference/generate-content)

本轮参与机制删减了对所有成员统一施加的简短、不催促等社交要求。成员依据自己的特质、状态和目标决定参与；已有后续预约用于观察交流进展。成员自行决定继续或结束，不按消息数和工具轮数收尾。个人主动性与最新验证见 [个人活动和独立交流](docs/personal-activity.md)。真实辩论与 UI 验收、失败记录和适用边界见 [参与机制减法与辩论验收](docs/participation-simplification.md)。

## 运行方式与边界

- 成员直接进入行动，拿到自己的特质、当前状态、相关经历和可用工具；没有 `speak / explore / revisit / pass` 前置分类，没有 `already_spoke`、首轮发言标记、按 @ 排序或全员屏障。消息使用 `send_message` 发送，发送后还可继续工具与交流；结束行动单独返回运行结果。期间收到同伴的新话，会在尚未发送前交给本人重看，系统不统一决定赞同、补充或沉默。不同成员独立运行，同一成员的跨场景行动串行以保留其经历一致性。
- 成员看过的消息位置和是否说话分开记录。当前状态和目标以一小段带来源的自然语言保存，可随新消息变化或清除，不建立人格分数、心情数值或固定轮流职责。聊天内关注仍保留；另有一段属于本人、可修改的近期关注。个人活动能召回自己对相关人的理解，原来源与更正版本仍保留。
- 相似措辞由发言成员结合上下文自行判断，不用中央相似度阈值删掉自然附和、共情或接梗。选择了不同人格不保证每句话都不同；实际多轮对话是否有趣需要观察，不能由消息数量或发言覆盖率证明。
- 明确修改角色本身的性格、兴趣或互动方式时更新人物说明；只针对某个人的相处要求属于该成员的相处理解，临时任务留在当前交流。情景举例含义不清时保持宽泛表达。问题的回答归属于提问成员；选择题工具一次只保留一个打开的问题，用户改聊其他事不需要点“跳过”。
- 人物说明保持稳定，只由用户编辑、角色设置问答或明确的对话设置修改。日常交流与探索保留具体经历，不再启动后台人格演化。资料页与系统身份复用同一份人物正文；当前场景只更新消息和控制。详见 [稳定的人物与实际经历](docs/personality.md)。
- 用户消息、修订号和待处理工作在同一事务落盘。新消息会取消该聊天正在生成的内容；即使外部请求未及时取消，旧修订也不能发布回复、保存成果或改写记忆。
- 公开聊天和研究是不同工作。“先别聊”立即停止公开讨论，研究可继续；“不用研究”立即停止该聊天的研究。带具体对象的自然语言由模型结合现有工作解释；模型不可用时，精确停止短语仍立即生效。恢复、局部停止、改方向也可用自然语言表达。
- 研究与个人探索可在过程中直接分享，不再经过额外的分享审批。尚未分享的作品属于作者，公开后的具体版本可在对应聊天中发现和阅读；后来的未公开草稿不替换历史分享。是否提醒用户由消息的 `notify` 决定。浏览器通知只有在用户点击“开启通知”、页面仍打开且处于后台时可用。关闭所有页面期间不会发系统推送，消息完整保留供回来查看。
- 所有成员都具备本地文稿与 HTML 创作能力；新成员默认提供搜索和阅读，联网能力仍取决于实际服务配置。提问、经历、历史检索、安排后续和取消自己的待办等工具按当前情境提供。没有终端执行、第三方联系、消费、账户修改或公开发布工具。
- 人物说明、当前挂念、有效方向与未完成工作常驻；旧聊天、记忆、成果通过本地工具检索。行动中随时可以查历史或整理经历；模型可选择新话题起点让无关旧原文退出默认窗口，记录不删除。长消息摘录保留头尾，完整原文可翻页。完整请求先折叠可回读工具正文，保守估算超限时使用 Responses 输入计数；确实需要时调用原生 `/responses/compact`，保留完整返回窗口，后续工具循环使用新窗口。恢复时保留已保存成果的回读线索，不要求用户缩短自己的问题。具体设计与验证见 [上下文与协调](docs/context-and-coordination.md) 和 [本次 IM 与职责改进](docs/im-and-responsibilities.md)。
- 组织职责从真人对话形成，例如「@小舟，以后需要一起做事时你帮忙张罗」或「这次让小岚组织」。长期群约定与具体事项的临时职责分别保留，群详情只展示实际约定与来源。负责人用 `delegate_work` 真正分工，可以授权别人组织子事项；接收者保留自身特质。结果、失败或暂停触发一次复看；交接保留成果并转移待处理回报，撤销职责不取消研究，取消事项则收束相关后续。完成后可以结束临时职责。
- 经历用带来源的自然语言笔记表达，不做人格分数或关系数值。群内行动默认读取本群记录；个人活动可以显式查看本人所在聊天。成员读取自己的理解笔记，也可以携带自己的经验进入其他群和私聊。是否分享由成员结合自己的特质、关系、语境和用户明确要求决定。
- 成果实际保存于 SQLite，修改生成新版本。聊天中显示真实保存的成果卡片；HTML 支持预览、源码、版本选择和下载，Markdown 支持阅读和下载。继续聊成果会保留未发送草稿。预览在不透明来源的沙箱中运行页面脚本，不授予聊天 DOM、存储、弹窗或表单权限；CSP 限制外部资源和联网 API，但不能宣称完全网络隔离（浏览器仍允许框架导航自身）。下载的 HTML 是原始文件。
- 公共提示保留身份、用户当前指示、工具和数据语义，不统一规定严谨、简短、克制或多主动。没有额外模型审核并改写成员的观点、消息和作品；工具保存作者实际提交的内容。
- 成员可以用 `schedule_followup` 为具体关注安排相对延时或带时区绝对时刻的一次重新考虑（不支持周期 cron），或用 `cancel_work` 撤销自己的未执行后续；到期先由本人读最新上下文，再决定是否行动，同伴可以接续真正发布的新话。个人活动按成员的时钟唤醒，不要求群里有旧话题或未完成目标，也不因沉默指数退避。人物本身的兴趣可以成为搜索或创作的方向；分享对象由本人选择。真人到来会中断相关成员的在途个人活动，断点保留，先处理眼前交流。
- 自主后续保留来源，用于用量统计和资源排队；总预算对所有请求生效，不再另设后台子额度。普通分享默认不通知，行动、公开交流和系统通知仍分别决定。
- 请求短暂故障在该请求处有限重试；持续故障保留行动现场。动态中的恢复入口重启原工作，不伪造催促消息。成功工具结果可复用，发送与清除现场原子提交，避免故障重放。运行诊断留在详情，不默认进入角色上下文。见 [执行机制简化](docs/execution-simplification.md)。
- 同一成员跨场景共享身份和可携带经历，不代表采用不同底层模型或独立事实来源；多个成员意见一致不能当作独立证据。
