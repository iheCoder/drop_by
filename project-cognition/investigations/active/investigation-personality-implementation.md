# 稳定人格、上下文顺序与重复来源：实现和验收

日期：2026-11-08。前序：[简化实验](investigation-personality-subtraction-validation.md)。本次按用户明确授权，把实验支持的简化落实为产品代码，并更新现有服务供实际体验。首次评价受他人纯态度影响仍是未解决项，不将本次升级命名为“趋同已修复”。

## 实现

- 人物说明仍是资料页可见、可编辑的 `Member.Profile`。创建、直接编辑、明确对话设置和情景问答保留；删除后台人格改写及前台聊天/工具的成长来源登记。没有新增人格分类、变化门槛、锁定字段或审核模型。
- 资料正文直接进入系统身份，仅一份；现场 `self` 保留身份标识、版本和能力。合并公共运行提示，保留当前行动所需的任务说明，不给全部成员加入独立、固执、体谅或反对要求。模型与推理配置未改变。
- 新现场追加到旧行动之后。`apply_instruction` 与其他工具同批时先完成工具配对，再交付新现场；唯一人物正文同步更新，恢复和整理不带回旧资料。
- 已完成的行动来由退出续接窗口，独有的触发原话/引用仍保留；跟聊沿用旧触发 ID 时不重播旧原话。新的研究/预约仍可获得自己的来源。
- 成功发送按消息 ID、正文与状态核对：调用参数保留原文，回执去掉相同正文的回显，群聊自动回流不再重复交付。原始工具结果和消息完整保存、可读回；不按相似措辞删除别人的消息，不拆改原生调用及不透明项目。
- 旧库启动时停止未完 `reflect` 工作，删除专用来源引用/游标表。既有人物、历史版本、消息、工具、作品与记忆不重写。旧自动更新版本继续可查看和手工恢复。

## 旧窗口兼容

旧实现把最新原话倒插到系统提示之后。若头部原话批次严格倒序、与后面的行动来由一一对应，就能把各批放回相应行动之前；正式库还存在“最早首轮只有原话与工具链、尚无独立来由”的格式，单独还原该首轮后再配对后续行动。

该修复在载入工作窗口和恢复断点时执行，不需要清空上下文或新增版本字段。缺少对应关系或已压缩的历史不猜测位置；后续新现场均按新顺序追加。不同人的观点、原生工具配对及完整原始内容保持。

## 结构、恢复与迁移验证

- 全量 `go test ./...`、`go test -race ./...`、`go vet ./...` 通过；前端脚本 `node --check` 与 `git diff --check` 通过。
- 新增连续三轮实际 Engine 测试：原话 1 → 回应 1 → 原话 2 → 回应 2 → 原话 3；每条已确认正文只交付一次。工具结果仍可完整回读，日常行动不修改人格。
- 验证不同成员相同措辞仍保留、失败发送不能当作已交付、回执扩展字段与原生协议保留；去重重复执行结果不再变化。
- 明确修改、同批整理、修改后恢复、未发送草稿重判、待发布结果恢复、整理后故障续接及迟到的用户设置冲突测试均通过。旧库的 pending/running/waiting_budget/paused/failed 整理工作停止，完成记录与历史版本保留。
- 正式 SQLite 经 backup 复制到独立目录后，用实际 `OpenStore` 和 `loadWorkingContext` 验证。对 members、profile_versions、messages、tool_runs、artifacts、memories 逐行哈希，迁移前后完全一致。
- 副本有 16 个工作窗口，5 个满足完整顺序还原条件（小说群占 3 个），16 个减少了重复载体。小说群另 1 个旧窗口缺少一处对应关系，历史位置保持，后续新输入按新顺序追加。总序列化文本由 1,471,332 字符降到 1,308,877 字符，约减少 11.0%；所有可识别消息 ID 与正文均保留。该数字不是 token 节省率或行为改善率。
- 最终副本升级停止了 2 项仍可运行或恢复的旧 `reflect` 工作；五种状态与旧失败工作不能经通用恢复入口重新运行的行为另有专门旧库测试。

原始副本验收记录：`data/personality-investigation/implementation/snapshot/upgrade-report.json`。该目录是忽略提交的本地测试数据。

## 实际模型连续验收

在独立数据库运行生产创建接口、成员行动、工具与问答，没有向正式群发送测试消息。共 32 次计费请求，累计估算 $0.108015，无未结算预留；包括真实网页读取与 HTML 作品保存。

| 场景 | 实际结果 |
| --- | --- |
| 仅名字创建 | 生成可见且持久的小禾人物说明，包含料理、植物、观察与交流倾向 |
| 职业外聊天 | 设计师聊猫碰倒杯子，以猫的口吻接话，没有转向设计分析 |
| 临时要求 | “这次说短点”给出简短晚饭建议，人物版本仍为 0 |
| 用户不喜欢极简 | 说明自己喜欢简洁、但认为必要细节值得保留，人物版本仍为 0 |
| 明确调整角色 | 实际调用 `apply_instruction`，外向/主动开话题进入资料，版本变为 1 |
| 含糊产品例子 | Grok bot 没有进入长期人物说明，版本仍为 1 |
| 探索与制作 | 实际读取 Excalidraw/tldraw 资料，保存《接一笔》HTML 演示；没有自动更新人物 |
| 后续行为 | 能沿用刚才的接力想法讨论故事玩具，换回猫与游戏时自然接话；版本仍为 1 |
| 同一话题不同成员 | 阿澈选择活字印刷，小禾选择菜市场与料理，也回应了同伴的兴趣 |
| 真实情景卡片 | 用户选择先做小样、边试边聊，人物说明按该选择更新 |

真实产物是模型生成并保存的演示，没有另行浏览器验收其交互，不把“保存成功”写成原型已通过实测。上述场景也不是长期多人盲测，不能据此声称首次评分不再受他人态度影响。

记录：`data/personality-investigation/implementation/live/personality_eval_9c16c50837b56133ff39bdc7.json`、`personality_question_223dc96de56fe2e42465f5b7.json`。费用在同目录独立 SQLite 账本中。

## 服务更新

使用现有 `127.0.0.1:8090` / `https://www.dropby.ai` 入口和原模型配置。部署前保存旧二进制与 SQLite 备份，正常结束旧服务后替换构建、恢复运行；核对实际构建版本、两个入口、资料页脚本、成员资料与旧群读取。HTTPS 代理沿用现有配置。

升级不自动把已经发生的旧人格变化回滚为创建版本，也不清除旧群讨论。用户可以从当前可见人物继续体验，或在变化历史中选择希望使用的人物版本。结构缺陷修复与长期人格效果仍应分别观察。
